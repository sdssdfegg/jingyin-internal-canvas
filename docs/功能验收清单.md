# 功能验收清单

适用目录：`D:\RJ\静音AI绘画V5（源码）`

更新时间：2026-08-14

本文用于每次改动后验收项目，尤其保护快捷生成、批量生成、批量换装和局部回贴这些 P0 功能。

## 1. 验收分级

### 1.1 P0 必测

只要改动涉及前端主页面、批量工作流、图片上传、图片处理、服务端接口、SKILL、保存或发布，都必须测：

- 快捷生成。
- 批量生成。
- 批量换装。
- 局部回贴。
- 保存图片。
- 下载图片。

### 1.2 P1 相关时测

改到对应模块时测：

- 换背景。
- 换脸。
- 设计稿。
- 详情主图。
- 图片编辑。
- 批量改尺寸。
- 参考生图。
- AI 质检。

### 1.3 P2 暂不强制

除非本次改动涉及，否则不强制测：

- 无限画布。
- 素材库。
- 历史搜索。
- 项目分组。

## 2. 每次提交前基础检查

每次修改文件后，提交前至少执行：

```powershell
D:\RJ\node\npm.cmd run check
```

如果改了前端组件、样式、打包相关文件，再执行：

```powershell
D:\RJ\node\npm.cmd run build
```

如果改了发布嵌入资源或发布脚本，再执行：

```powershell
D:\RJ\node\npm.cmd run build:assets
node --check server\static-assets.generated.js
```

注意：

- 在当前 Windows 环境里，直接运行 `npm` 可能被 PowerShell 执行策略拦截，优先使用 `D:\RJ\node\npm.cmd`。
- 检查通过后再 commit。

## 3. P0 快捷生成验收

### 3.1 无参考图生成

步骤：

1. 打开画板。
2. 进入快捷生成。
3. 填写 API Key。
4. 不上传参考图。
5. 输入简单提示词。
6. 点击生成。

通过标准：

- 能提交任务。
- 有运行状态。
- 成功返回图片。
- 结果图能预览。
- 结果图能下载。
- 结果图能保存到目录。
- 刷新页面后历史不异常。

### 3.2 带参考图生成

步骤：

1. 快捷生成上传一张图。
2. 输入参考图相关提示词。
3. 点击生成。

通过标准：

- 上传缩略图显示正常。
- 能删除和重新上传。
- 生成接口正常。
- 结果不出现明显空白或比例错误。

### 3.3 快捷生成普通裁剪

步骤：

1. 上传参考图。
2. 使用普通裁剪。
3. 提交生成。

通过标准：

- 裁剪只改变上传给模型的图片内容。
- 不触发局部回贴。
- 不追加批量换装 SKILL。
- 结果不出现截图、画中画、白边误读。

### 3.4 快捷生成局部回贴

步骤：

1. 上传图1原图。
2. 开启局部回贴。
3. 框选或涂抹服装局部。
4. 可选上传图2作为服装或细节参考。
5. 使用 GPT 图片模型生成。

通过标准：

- 只处理选区或涂抹区域。
- 原图人脸、背景、身体位置不乱变。
- 贴回位置正确。
- 边缘过渡自然。
- 原图尺寸尽量保持。
- 未修改区域不出现明显全局变糊、低清压缩感或细节变软。
- 脸、发丝、背景纹理和服装肌理接近原图清晰度。
- 能继续保存和下载。

失败判定：

- 人脸被重绘或错位。
- 背景大面积改变。
- 局部结果贴偏。
- 选区外出现明显 AI 重构。
- 画布尺寸被错误缩小。
- 脸部或肤色出现轻微糊化、重采样感、颜色没有自然晕染开的状态。
- 选区外未修改区域也明显变软或有 JPEG 压缩糊感。

## 5. P0 批量换装验收

### 5.1 基础批量换装

步骤：

1. 图1上传多个女装模特图。
2. 图2上传真人穿着服装图。
3. 图3留空。
4. 使用默认批量换装提示词。
5. 点击生成。

通过标准：

- 每个图1模特都生成结果。
- 模特姿势和位置尽量不变。
- 人脸不要明显 AI 化或换脸。
- 背景不要明显改变。
- 服装来自图2。

### 5.2 版型一致性验收

重点看：

- 袖长是否一致。
- 袖克夫长度是否一致。
- 袖口位置是否一致。
- 袖筒宽松度是否一致。
- 袖子卷起或放下的状态是否一致。
- 衣长是否一致。
- 衣摆是否按图2扎入或自然放下。
- 裤长是否一致。
- 领口形状是否一致。
- 扣子扣合数量和开合状态是否一致。
- 拉链高度、腰带系法、领口打开程度是否一致。
- 扣子、门襟、缝线是否一致。
- 面料纹理是否一致。
- 宽松款有没有被生成成正装感。

通过标准：

- 多个模特像穿同一件衣服的不同尺码或不同体型适配，而不是相似但不同款。
- 核心细节不能随机漂移。

失败判定：

- 有的长袖到手腕，有的到手掌，有的变九分袖。
- 袖克夫一张长一张短。
- 宽松款变成修身正装。
- 图2的细节在不同结果里随机消失。
- 图2衣摆是扎进去的，结果却变成未扎。
- 图2袖子是卷起的，结果却变成放下或半卷。
- 图2扣子扣了固定数量，结果却随机多扣、少扣或全开。

### 5.3 固定母版分析验收

如果使用母版版型分析：

1. 选择图2固定服装。
2. 执行母版分析。
3. 检查返回的版型描述。
4. 再执行批量换装。

通过标准：

- 分析内容能描述服装类别、版型、袖口、袖长、衣长、松量、面料等关键点。
- 生成结果一致性优于未分析时。
- 替换、重新裁剪或切换图2固定母版时，已有母版提示词不自动删除，只暂停锁定；只有用户删除母版图、清空图2或清理上传缓存时才清空母版提示词。

### 5.4 结果重刷与覆盖验收

步骤：

1. 对一张成功结果点击重刷。
2. 等待生成新的重刷候选卡。
3. 将候选卡图片拖到原不合格结果卡上。

通过标准：

- 原结果不会在点击重刷时立刻被覆盖。
- 重刷候选能正常生成、预览、保存和下载。
- 拖拽覆盖后，原结果卡显示候选图，候选卡从队列移除。
- 覆盖后选中状态、预览和历史不会指向已移除候选。
- 历史结果缺少原始上传图时，重刷按钮不可用或给出提示。

### 5.5 裁剪生成回流验收

目标场景：

- 图1是大图，用户先裁成 3:4 半身或其它稳定构图。
- 普通裁剪生成本身不偏移，希望生成后回填到原图真实裁剪框位置，并导出完整原图尺寸。
- 回流比例使用图1裁剪弹窗里的本地预置：`1:1`、`3:4`、`4:3`、`16:9`、`9:16`。
- 不启用局部回贴，不改变当前默认提示词，不改 SKILL，不给生成请求追加回流语义。

步骤：

1. 图1上传高分辨率大图。
2. 对图1使用“手动裁剪”，在 5 个回流比例预置里选择目标比例。
3. 图2上传固定服装图。
4. 不开启图1局部回贴。
5. 使用默认批量换装提示词执行生成。
6. 打开结果预览并保存结果。

通过标准：

- 结果卡显示“裁剪回流”标记。
- 预览诊断显示原图尺寸、裁剪框尺寸、生成尺寸、完整大图尺寸和输出 Q。
- 生成请求仍是普通批量换装，不触发局部回贴，不让回流内容进入提示词或 SKILL。
- 输出结果尺寸等于图1原图完整尺寸，生成内容位于原真实裁剪框位置。
- 不出现局部回贴常见的边缘色差、腿部贴回错位或整张图二次压糊。
- 重刷候选拖拽覆盖后，旧结果卡仍保留正确的大图回流尺寸和诊断。
- 图2、图3使用普通裁剪时，弹窗显示“裁剪比例”而不是“回流比例”。
- 图2、图3裁剪后的图片只作为裁剪参考图参与生成，不写入 `cropReturn`，不触发回流，不参与局部回贴坐标和 SKILL 预置。

### 5.6 渠道错误和备用兜底验收

步骤：

1. 使用无效 KEY 执行一次生成。
2. 使用余额不足账号执行一次生成。
3. 模拟静音中转站返回 502/504 或超时，确认客户端不暴露底层渠道，前端统一显示“生成超时，请重新生成”，真实状态写入后台日志；备用上游切换由静音中转站内部处理。
4. 模拟主备都失败，查看前端错误。
5. 查看 `logs/generation.jsonl`。

通过标准：

- KEY 问题显示 API Key 无效或无权限。
- 余额问题显示余额不足。
- 图片过大显示图片过大。
- 渠道故障在前端只显示“生成超时，请重新生成”。
- 客户端响应不暴露备用渠道 URL、上游供应商名称、底层模型别名、请求格式差异、备用尝试明细或不同价格。
- 后台日志记录真实渠道、请求变体、状态码、失败原因和是否 fallback。

## 6. P0 局部回贴验收

### 6.1 批量局部回贴基础

步骤：

1. 图1上传模特原图。
2. 在图1上框选服装区域。
3. 图2上传要替换或参考的服装图。
4. 使用 GPT 图片模型。
5. 执行生成。

通过标准：

- 生成变化只发生在局部区域。
- 贴回原位。
- 原图其它区域保持。
- 人脸、背景、手部、身体位置不被模型重构。
- 原图高分辨率保留。
- 未修改区域不因贴回合成被二次压糊，脸、发丝、背景纹理和服装肌理不能明显低于原图。
- 浅黄色、米黄色、浅粉色等服装不会被肤色保护误擦成半截换装。
- 结果诊断里能看到裁剪 Q、输出 Q、清晰补偿状态；输出 Q 不应异常偏低。

交互验收：

- 按住 `Alt + 鼠标左键` 拖动选框或角点时，选框以当前中心点放大缩小。
- 选框中心缩放不越出原图边界，不改变当前比例。

### 6.2 蒙版局部回贴

步骤：

1. 选择涂抹蒙版。
2. 只涂需要修改的局部，例如袖口、扣子、口袋。
3. 生成并贴回。

通过标准：

- 未涂抹区域不被改变。
- 涂抹边缘融合自然。
- 小目标修改比大框选更稳定。

### 6.3 PS 回流验收

目标场景：

- 用户后续要把结果导入 Photoshop，在原位擦回人脸或其它区域。

通过标准：

- 输出尺寸和原图一致或尽量一致。
- 人物位置不偏移。
- 图层对齐思路可行。
- 局部贴回结果不影响 PS 原位擦回。

### 6.4 GPT 批量局部回贴已知问题验收

当前已观察到的问题：

- 批量局部回贴时，极少数结果会带入图2未选中的服装部分。
- 一部分结果存在局部上下位置对不上或轻微偏移。
- GPT 生成的局部颜色和原图有轻微区别。
- 框选包含上方人脸一小半、下方腿部一部分时，脸部可能出现轻微糊化或颜色没有自然晕染开的感觉。
- 局部回贴贴回后整张成片可能整体变糊，未修改区域也出现细节变软或压缩感。

后续修复时必须单独验证：

- 不影响 GPT 非局部批量换装，因为当前直接原图上传的批量人物姿势一致性正常。
- 不影响已稳定的快捷生成局部回贴。
- 不把问题简单交给更重的 SKILL，优先检查选区、贴回、融合、保护区和上传图构造。
- 用户明确要求删除发圈、头饰、配饰、道具、文字或水印时，目标必须完整删除，不留半截、残影或同色替代物。
- 对比原图未修改区域，确认局部回贴后的整张输出没有明显全局清晰度下降。
- 确认保存和下载高分辨率局部回贴成片正常，不因文件体积变大失败。
- 结果预览诊断应显示“输出 PNG无损”，未修改的人脸、发丝、背景纹理不应再出现明显 JPEG 二次压缩感。
- 同一批局部回贴应自动跑完，但请求节奏不应和单张明显不同；失败图单张重跑正常时，优先复查批量并发和服务端队列。

## 12. 当前重点测试素材建议

为了稳定女装电商场景，建议固定一组测试素材：

- 3 到 5 张不同姿势的女装模特图，作为图1。
- 1 组带明确袖口、袖克夫、袖长、宽松度的真人服装图，作为图2。
