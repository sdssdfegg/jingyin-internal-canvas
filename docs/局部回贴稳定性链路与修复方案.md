# 局部回贴稳定性链路与修复方案

适用目录：`D:\RJ\静音AI绘画V5（源码）`

更新时间：2026-08-14

本文用于规范“局部回贴”后续开发。局部回贴是嵌入批量生成和批量换装里的底层能力，不作为单独业务板块；后续优化必须优先保护快捷生成、批量生成、批量换装这几条主流程。

## 1. 当前问题记录

来自实际测试的 GPT 批量局部回贴问题：

- 偶发把图2中未被用户选中的服装部分带入结果。
- 局部生成后上下位置对不上，或贴回时出现轻微偏移。
- 局部区域与原图存在轻微色差，边缘晕染不够自然。
- 人脸或肤色区域有轻微糊化、发灰、没有完全融入原图的感觉。
- 局部回贴虽然解决了偏移，但合成后的整张成片可能比原图明显变糊，不只是脸部，未修改区域也会出现压缩感或细节变软。
- 直接原图上传、不启用局部回贴的 GPT 批量换装目前人物姿势一致性正常，这条链路不要作为本问题修改范围。
- 2026-08-13 新观察：把大图先裁成 3:4 半身图后走普通批量换装，结果没有发生偏移；因此新增“裁剪生成回流”作为局部回贴不稳定时的替代链路，保持默认提示词不变，只在生成完成后把结果等比例缩放并回填到原图真实裁剪框，最终导出完整原图尺寸。

## 2. 当前代码链路

### 2.1 前端框选和裁剪

主要位置：`src/outfit-workflow.jsx`

1. 用户在图1上开启局部回贴。
2. 矩形模式会调用 `cropOutfitLocalEditFile(..., { withContext: true })`。
3. 涂抹蒙版模式会根据蒙版边界生成 `maskCropRect`，并保存 `maskDataUrl` 和 `maskBounds`。
4. 前端保存：
   - `cropRect`：最终贴回原图的位置。
   - `contextRect`：给模型看的周边上下文区域。
   - `sourceWidth/sourceHeight`：原图尺寸，用于最终保持 8K 或高分辨率输出。

### 2.2 生成请求

主要位置：`runSingleTask()`

1. 如果存在 `localEdit.cropFile`，图1上传给模型的是局部裁剪图，不是整张原图。
2. 请求 payload 里带：
   - `deferAutoSave: true`
   - `localEdit.enabled: true`
   - `localEdit.editMode`
   - `localEdit.cropRect`
   - `localEdit.contextRect`
   - `localEdit.maskBounds`
3. 图2仍作为服装事实来源上传。
4. 图3只在用户提示词明确说明时作为弱参考，不默认介入。

### 2.3 服务端提示词

主要位置：`server/outfit-skill.js`

1. 局部回贴会进入 `buildQuickStyleOutfitLocalEditPrompt()`。
2. 提示词要求图1是局部坐标、人物姿势、脸部质感、背景光影和边缘的唯一标准。
3. 图2是服装事实来源。
4. 已加入服装事实锁，约束袖口、袖长、衣摆扎法、卷袖、扣子、拉链、腰带、领口等穿法。

### 2.4 前端贴回

主要位置：`composeOutfitLocalEditBlob()`

当前本地化状态：

- 局部回贴的裁剪、贴回、融合、清晰度补偿和最终导出已经在前端本地 Canvas 完成，不交给模型决定最终坐标和整图尺寸。
- 当前还不是独立的本地后端/GPU 贴回引擎；如果后续要利用 8G 显卡或本地小程序能力，应新增“本地贴回引擎 V1”，只做原图、生成图、坐标、蒙版、羽化和导出，不参与提示词、SKILL 和上游模型请求。
- 能在本地完成的裁剪、贴回、回流、缓存和下载，不写入 SKILL，避免模型误解流程后影响出图。

1. 先加载原图，建立原图同尺寸 canvas。
2. 再加载模型返回的局部生成图。
3. 如果有 `contextRect`，先把生成图铺到上下文区域，再从中裁出 `cropRect` 对应的 patch。
4. GPT 路径当前使用：
   - `frameFit: stretch`
   - `autoAlign: true`
   - `maxShift: 18`
   - `lowerBodyFocus: true`
   - `alignMinImprovement: 0.5`
   - `colorMatch: true`
   - `colorMatchStrength: 0.36`
   - `colorMatchMaxDelta: 8`
   - `colorMatchFadeRatio: 0.12`
   - `colorMatchPreventLightening: true`
   - `colorMatchMaxLumaLift: 1.5`
   - `sharpenPatch: true`
   - `sharpenStrength: 0.18`
   - `protectSkinAndFace: true`
   - `protectSkinTopRatio: 0.32`
   - `protectSkinBlurRatio: 0.04`
   - `protectSkinBlurMax: 68`
   - `rectFeatherRatio: 0.045`
   - `rectFeatherMax: 48`
5. Banana 路径当前使用颜色匹配：
   - `colorMatch: true`
   - `colorMatchStrength: 0.72`
   - `colorMatchMaxDelta: 18`
   - `colorMatchFadeRatio: 0.16`
6. 最终把 patch 按 `cropRect.x/y` 贴回原图，输出仍保持原图尺寸。
7. 当前局部裁剪图使用高质量 JPEG 阶梯导出，优先保留 0.98/0.96/0.94/0.92，目标上限 16MB；避免把模型输入的局部区域先压糊。
8. 最终贴回成片默认使用 PNG 无损导出，避免 8K 原图在贴回后整张 JPEG 二次压缩，导致人脸、发丝、背景和未修改区域变软。
9. 批量局部回贴结果会在 `result.localEdit.diagnostics` 保存贴回策略、对齐、色彩匹配、清晰度补偿、最终输出质量、羽化和贴回矩形等诊断字段，便于后续定位偏移、色差和画质变糊。
10. PNG 结果会先以运行时 Blob 快速预览，再通过 `/api/cache-result-image` 缓存到项目 `data/results`，历史记录使用本地结果 URL，不把 8K PNG 塞进浏览器历史。
11. 2026-08-14 当前批量稳态基线：前端局部回贴批量请求并发上限固定为 10，请求错峰 250ms；本地裁剪预处理仍使用小并发 2，避免多张大图同时 Canvas 编码导致界面卡顿。
12. 服务端图片请求队列默认/上限同步为 `IMAGE_CONCURRENCY_LIMIT=10`，用于 8-10 张一批的局部回贴压测；如果后续渠道承载不稳，再把“本地预处理并发、前端提交并发、服务端队列并发”分开调。
13. 2026-08-14 修正批量局部回贴脸/脖子保护：GPT 贴回时把上方皮肤保护范围从 12% 提高到 32%，但仍使用皮肤候选和连通块过滤，并同步排除浅黄、米黄、淡粉、淡紫等服装误判为皮肤，避免图2母图脸/脖子颜色贴入图1。

### 2.5 裁剪生成回流

主要位置：`src/outfit-workflow.jsx`

目标：当普通裁剪生成本身不偏移时，不再强行走局部回贴，而是走普通生图，再把结果回流到图1原图同一裁剪位置，最终保持完整原图尺寸。

触发条件：

1. 图1使用“手动裁剪”。
2. 图1没有启用局部回贴。
3. 不是设计稿、批量姿态等不适合裁剪回流的工作流。
4. 继续使用当前默认批量换装提示词，不追加局部回贴提示词。
5. 回流比例是前端本地预置，仅用于裁剪和回填坐标，不能写入提示词、SKILL 或服务端语义。

当前链路：

1. 图1裁剪弹窗提供 `1:1`、`3:4`、`4:3`、`16:9`、`9:16` 五个回流比例预置。
2. 裁剪确认时记录图1原图尺寸、原图中的真实裁剪框 `cropRect`、目标比例、原裁剪框像素尺寸和完整原图尺寸。
3. 批量任务创建时把该信息写入 `task.cropReturn`，只作为前端本地后处理元数据。
4. `runSingleTask()` 仍按普通批量换装发送图1裁剪图和图2服装图，不设置 `localEdit`，不在 payload 中增加回流语义。
5. 模型返回后，本地先绘制完整原图画布，再把生成图等比例缩放到 `cropRect` 区域并贴回同一位置，最后导出高质量 JPEG。
6. 结果卡显示“裁剪回流”标记，预览里显示裁剪回流诊断：原图尺寸、裁剪框尺寸、生成尺寸、完整大图尺寸和输出质量。

当前边界：

- 当前输出是“完整原图尺寸的大图”，普通裁剪生成结果只回填到原图 `cropRect` 同一位置。
- 它解决完整大图回流需求，但暂不做局部回贴的蒙版、羽化、自动对齐和颜色融合；如果裁剪边界本身穿过明显背景或身体边缘，仍需要通过裁剪范围或后续融合策略优化。
- 它的价值是避开局部回贴的边缘色差、全图二次压缩和局部贴片错位风险，优先验证普通裁剪生成在批量里是否足够稳定。
- 不改默认提示词、不改 SKILL、不让局部回贴规则参与，避免破坏当前已观察到的不偏移效果；回流只做本地预置和本地合成。

## 3. 关键风险判断

- GPT 局部回贴不稳定，不等于 GPT 非局部批量换装不稳定；后续修复必须只命中 `localEdit` 分支。
- 偏移可能来自两处：
  - 模型返回图相对局部输入发生重构。
  - 前端把上下文生成图裁回 `cropRect` 时映射不够稳。
- 2026-08-13 用户回归反馈：3 张 GPT 批量局部回贴中 1 张正常，2 张腿部对不上；其中 1 张图1来自大半身图截取，2 张为全身图。本轮优先处理下半身坐标贴回。
- 2026-08-13 进一步反馈：将批量里对不齐的一张单独生成后可以正常，说明根因可能不只是模型局部重绘，也可能是批量并发、任务绑定、裁剪文件或坐标快照在批量链路里不够稳定。用户业务一轮通常是 8 组服装，但“8 张自动跑”和“8 张同时打到上游”不是一回事，因此当前改为自动批量、受控并发 2、错峰启动，并继续保留每任务重新裁剪和 `taskBinding` 诊断。
- 2026-08-13 R3 复测反馈：4 张里 3 张腿部已经正常，说明受控并发 8 和任务绑定方向有效；剩余 1 张出现浅黄色上衣横向半截换装，判断为肤色/脸部保护误把浅黄服装当皮肤擦回，因此当前收紧肤色识别并把保护高度从 18% 降到 12%。
- 用户补充“去掉粉色发圈”时 4 张均未完整删除，说明删除对象不能只作为普通补充文本，需要在 SKILL 中增加显式删除优先级，特别是发圈、头饰、发饰、夹子、配饰、道具、文字和水印。
- 抬手、扶头、叉腰等动作会让模型倾向把图2长袖缩成九分袖；需要在 SKILL 里明确锁定袖口到手腕、掌根、手背或掌心的相对落点。
- 同批换装即使母版锁定，仍可能出现服装亮度不一致或 GPT 把图2服装变浅；需要把“图2原本亮度、颜色深浅、饱和度、面料光泽不提亮、不泛白、不降饱和、不改色”作为批量一致性验收项。
- 色差、颜色变浅和脸部轻微糊化通常来自：
  - 模型对肤色、脸部、背景进行了重新渲染。
  - GPT 本身把图2服装做了商业化提亮、柔光、泛白或降饱和。
  - 贴回 patch 的边缘色彩匹配如果过强，可能继续跟随图1原服装或周边光照把新服装抬亮。
  - 选区包含上半张脸或腿部时，模型会把不该重绘的人体区域当作可编辑内容。
- 全图画质下降通常不是模型重绘全部区域，而是局部回贴合成时先把原图绘制到同尺寸 canvas，再把整张结果重新导出为 JPEG；即使 JPEG 质量很高，原图未修改区域也会被二次压缩，8K 图尤其容易肉眼变软。
- 当前已把最终贴回成片改为 PNG 无损输出，并用本地结果缓存承接历史和刷新后的预览；长期如果还需要更接近 PS 工作流，可继续做分层 PSD/PNG 贴片输出，或只保存局部 patch 与原图坐标供 PS 回流。
- 图2未选中服装部分偶发进入结果，优先通过 SKILL 边界和图2服装部位锁解决，不优先通过裁剪图2解决。
- 裁剪生成回流不是局部回贴的替代品，而是“普通裁剪生成稳定时”的生产捷径；它已经回填完整原图尺寸，如果后续要 PS 分层擦回，再另做分层输出或局部 patch 坐标包。

## 4. 后续修复顺序

### 第一阶段：建立可回归测试

目标：先固定样本，避免凭单张结果判断改动好坏。

步骤：

1. 固定 3 到 5 张高分辨率图1模特图，至少包含正面、侧身、半身、露腿、复杂背景。
2. 固定 2 到 3 套图2服装，覆盖：
   - 衣摆扎入和不扎入。
   - 卷袖和不卷袖。
   - 扣子扣合数量不同。
   - 宽松版型和修身版型。
3. 每次测试记录：
   - 模型。
   - 是否局部回贴。
   - 选区模式：矩形或蒙版。
   - 选区是否包含脸、腿、背景边缘。
   - 是否出现偏移、色差、脸糊、图2越界迁移。

### 第二阶段：先调合成，不调生图主链路

目标：降低贴回偏移和色差，保持非局部换装不动。

建议步骤：

1. 给 GPT 局部回贴路径加入温和颜色匹配。当前已在前端贴回合成层启用，参数偏保守，待固定素材回归。
2. 把颜色匹配限定在边缘过渡带，不大面积改变服装主体颜色，避免破坏图2服装事实。
3. 给 GPT 色彩匹配增加防变浅护栏：`colorMatchPreventLightening: true`，最大亮度上抬限制为 `1.5`，避免程序侧把已经偏浅的结果继续抬亮。
4. 对 GPT 局部贴回开启上方肤色/脸部保护：当选区包含上半张脸时，尽量用原图脸和肤色从贴片中擦回，降低“脸轻微糊、肤色晕不开”的概率；保护区不能覆盖到上衣主体，浅黄、米黄、浅粉等服装要排除肤色误判。
5. 2026-08-14 追加：上方肤色/脸部保护改为“原图和生成图都像皮肤”才进入候选，并按连通块过滤横向大色带；浅黄、米黄、浅粉、淡紫等服装色继续排除，避免把肩颈附近的浅色上衣误当作皮肤擦回旧图，导致“衣服只换到一半”。
6. 2026-08-14 追加：进一步收窄 GPT 上方肤色/脸部保护区，并过滤过低、过宽、过高或过稀疏的皮肤候选连通块；同时在局部换装 SKILL 里明确图2未选中的下装、鞋靴、腿部和下半身姿势全部无效，避免只换上衣时把图2母图下半身生成进来。
7. 对 GPT 路径增加贴回诊断字段，记录：
   - 是否启用 `autoAlign`。
   - 实际最大偏移搜索值。
   - 是否启用 `colorMatch`。
   - 是否启用 `colorMatchPreventLightening`，以及 `lighteningLimited` 是否拦截了亮度上抬。
   - 是否启用 `protectSkinAndFace`，以及 `skinProtect` 是否实际保护了肤色区域、候选像素数、保留连通块数和被过滤连通块数。
   - 羽化参数。
   第一轮已写入 `result.localEdit.diagnostics`，后续回归记录见 `docs/局部回贴回归验收记录.md`。
7. 对人脸附近选区先保守处理，不主动锐化或磨皮，避免把糊脸问题扩大。
8. 针对“整张成片变糊”，局部裁剪保持高质量 JPEG 阶梯导出，最终贴回成片改为 PNG 无损导出；结果预览诊断显示裁剪 Q、输出 PNG 无损、输出字节数和清晰补偿状态。
9. 对 GPT 批量局部贴片增加轻微清晰度补偿，只处理贴片区域，不对整张 8K 图做锐化；贴片过大时自动跳过，避免浏览器卡顿。
10. 快捷生成局部回贴同步使用高质量裁剪、高质量最终输出，并在局部回贴时保留第一张局部裁剪图，不再按普通参考图强行压到 4MB 内。

### 第二点五阶段：排查批量链路串扰

目标：验证“单张正常、批量失败”是否来自批量执行方式，而不是图像合成参数。

步骤：

1. 当批量任务中任意图1启用局部回贴时，本轮使用受控并发 2，并让局部请求错峰启动；用户仍然一次提交多张，但模型请求不再同一秒集中冲到上游。
2. 每个任务执行前重新从该任务图1原图裁剪 `cropFile`，不要只依赖创建任务时保存的裁剪文件对象。
3. 在 `result.localEdit.diagnostics.taskBinding` 中记录：
   - `taskId/order`
   - 图1名称和图1 id
   - `cropFile/uploadFile/originalFile`
   - `cropRect/contextRect`
   - `batchMode`
4. 如果 R7 在受控并发 2 + 服务端请求队列下稳定，后续可逐步试探 `IMAGE_CONCURRENCY_LIMIT` 或前端局部并发上限；如果仍失败，再回到模型生成结构保护和局部 mask 引导。

### 第二点六阶段：服装穿法与电商平整度

目标：解决抬手长袖变九分袖、同批亮度不一致、衣身杂乱褶皱影响上架质感的问题。

步骤：

1. 在批量换装和局部换装 SKILL 中锁定图2袖口相对落点：手臂抬起、扶头、叉腰、手插袋或肘部弯曲时，仍按图2到手腕/掌根/手背/掌心的相对位置执行。
2. 把服装亮度和颜色深浅一致写成同批约束：不允许随机提亮、变浅、泛白、降饱和、发灰、改色或让同一件服装出现不同曝光版本。
3. 把去褶皱定义为电商整理，不是重设服装：消除杂乱压痕、多余自然褶皱和凌乱皱团，保留轻微自然松弛垂感。
4. 保留图2服装细节：针织肌理、珍珠钻饰、钻扣、口袋、扣子、拼接线、版型线条不能被抹平、简化或重画。

### 第二点七阶段：裁剪生成回流验证

目标：验证普通裁剪生成在批量里能否比局部回贴更稳定，并保持默认提示词链路不被污染。

步骤：

1. 选择 3 到 5 张大图图1，使用普通“手动裁剪”裁成 3:4 半身或需要的构图。
2. 不开启局部回贴。
3. 图2上传同一件服装，使用当前默认批量换装提示词。
4. 生成完成后检查结果卡是否显示“裁剪回流”。
5. 打开预览查看诊断：原图尺寸、裁剪框尺寸、生成尺寸和完整大图尺寸应完整可见。
6. 保存或下载结果，确认导出的图片尺寸等于图1原图完整尺寸，生成内容回填在原裁剪框位置。
7. 对不合格结果点重刷，满意后拖拽覆盖原结果，确认裁剪回流诊断和输出尺寸跟随新结果。

通过标准：

- 普通裁剪批量生成的人物姿势和位置不出现局部回贴里的腿部错位。
- 不出现局部回贴边缘色差、色块断层或全图变糊。
- 默认提示词不变，不触发局部回贴 SKILL。
- 输出为完整原图尺寸，方便后续导入 PS 按原位继续擦回或精修。

### 第三阶段：再调局部 SKILL

目标：减少模型在局部区域内重画脸、肤色和图2非目标服装。

建议步骤：

1. 增强局部回贴提示词：
   - 明确只替换用户点名的服装区域。
   - 选区内出现脸、头发、手、腿、背景时，只作为坐标和肤色参考，不作为重绘目标。
   - 图2只迁移当前任务指定服装部位，未指定部位不得出现。
2. 对矩形模式增加一句：矩形包含的脸、腿、背景不等于要修改它们。第一轮已在局部换装 SKILL 中增加对应边界，待固定素材回归。
3. 对蒙版模式增加一句：只修改涂抹区域和服装必要贴合边界。
4. 保持图3默认不介入。

### 第四阶段：再评估交互

目标：让用户更容易选出稳定区域。

建议方向：

1. 在局部回贴面板中区分“矩形范围”和“真实修改范围”；当前已支持 `Alt + 鼠标左键` 以选框中心缩放，方便扩大或缩小包含脸部、腿部、上衣边缘的高风险选区。
2. 引导高风险区域使用蒙版模式，而不是大矩形覆盖脸部和腿部。
3. 结果区保留重刷候选机制：不合格结果先重刷出候选卡，满意后拖到旧结果上覆盖，避免同一张图堆出多张重复结果。

## 5. 验收标准

单次回归测试至少看以下指标：

- 贴回位置：人物肩颈、衣摆、袖口、腿部边缘没有明显上下错位。
- 边缘融合：选区边界没有硬边、灰边、明显色块。
- 脸部保护：脸、眼睛、鼻梁、嘴角、肤色质感没有明显变糊或变灰。
- 图2边界：只迁移任务指定服装，不把未选中服装部件带入图1。
- 显式删除：用户点名删除发圈、头饰、道具、文字、水印等对象时，目标完整消失，不留半截残影。
- 服装完整：不出现浅色服装被肤色保护误擦造成的半截换装。
- 原图保持：输出尺寸保持原图尺寸，高分辨率图不被降采样。
- 画质保持：未修改区域不能出现明显全局发糊、细节变软或低质量 JPEG 压缩感；脸、发丝、背景纹理和服装肌理应接近原图。
- 诊断可见：批量局部回贴结果预览应能看到裁剪 Q、输出 Q、清晰补偿等字段，便于判断问题来自模型、贴片缩放还是最终导出。
- 主链路保护：关闭局部回贴时，GPT 批量换装姿势一致性和原有流程表现不变。
- 裁剪回流：普通裁剪图1生成后，结果尺寸等于图1原图完整尺寸；预览能看到裁剪回流诊断；不出现局部回贴诊断和局部回贴提示词。
