# 提示词规则边界

适用目录：`D:\RJ\静音AI绘画V5（源码）`

更新时间：2026-08-14

本文用于约定：哪些规则应该写进 SKILL，哪些应该由前端预处理或本地后处理完成，哪些是用户补充提示词负责的内容。这个边界非常重要，因为当前项目的出图稳定性不仅取决于模型，也取决于不要让模型理解过多本地流程。

## 1. 业务背景

画板主要服务做电商设计的人群，目前重点是女装电商。

女装电商的核心痛点不是单张图“好看”，而是批量图能不能用于真实上架：

- 多个模特穿同一件衣服时，版型要一致。
- 袖口、袖克夫、袖长、衣长、裤长、领口、门襟、扣子、松量、面料细节和穿法要一致。
- 图2服装如果衣摆扎进裤腰或裙腰，批量结果不能变成未扎衣摆；如果袖子卷起，批量结果也必须保持卷袖；如果扣子扣了几颗，批量结果也应保持相同扣法。
- 抬手、扶头、叉腰等动作里，图2长袖到手腕/掌根/掌心的相对落点不能被模型改成九分袖或七分袖。
- 同批同一件衣服的亮度、颜色深浅、饱和度和面料光泽要一致，不能随机提亮、变浅、泛白、降饱和、发灰或改色。
- 电商成片可以去掉杂乱压痕、多余自然褶皱和凌乱皱团，但不能改变款式、版型、针织肌理、珍珠钻饰、钻扣、口袋、扣子和拼接线。
- 图1模特的姿势、位置、人脸、场景不能乱变。
- 最终图最好保持原图高分辨率，方便继续进 Photoshop 做局部擦回。
- 如果版型和细节漂移，批量生成就失去生产价值。

当前重点模型判断：

- GPT 图片模型配合局部回贴相对稳定。
- GPT 图片模型在快捷局部回贴中相对稳定，但批量局部回贴仍存在个别不稳定点，需要单独打磨。
- 香蕉系模型在局部回贴上的稳定性暂时达不到核心要求，不能作为局部回贴主力。

## 2. 三层边界

所有规则先分三层：

```text
前端预处理：上传前已经能决定的事
后端 SKILL：必须让模型理解的生图语义
本地后处理：模型出图后由本地程序完成的事
```

不要把所有规则都塞进 SKILL。SKILL 越重，模型越容易过度理解、过度重构，反而影响原位稳定。

## 3. 前端预处理负责什么

前端预处理负责“图片进入模型之前”的确定性处理。

应该放在前端预处理：

- 文件夹拖拽和批量上传。
- 图片排序、选择、删除。
- 图1、图2、图3通道归类。
- 普通裁剪。
- 局部回贴选区。
- 涂抹蒙版。
- 上传前压缩。
- 上传前比例适配。
- 图1非局部上传时的目标比例画布适配。
- 判断图3是否应该参与上传。
- 局部回贴所需的裁切区域生成。

原则：

- 能在上传前确定的，不交给 SKILL。
- 普通裁剪只是改变上传图片内容，不等于局部回贴。
- 局部回贴选区是坐标和画布能力，不是让模型自己决定贴哪里。

## 4. 后端 SKILL 负责什么

SKILL 负责“模型必须理解的任务语义”。

应该写进 SKILL：

- 当前任务是批量换装、换背景、换脸、设计稿、姿态还是自定义。
- 图1是主输入、原始场景、人物姿态、画面坐标和身份来源。
- 图2是固定需求通道，例如服装、人脸、背景、设计结构。
- 图3只有被用户明确提及时才是补充参考。
- 换装时图2服装是事实来源。
- 未被要求改变的图1内容必须保留。
- 用户明确写出删除、去掉、移除某个可见对象时，SKILL 需要提高该删除目标优先级，例如发圈、头饰、发饰、夹子、配饰、道具、文字、水印和标签；删除必须完整，不保留残影，但不能顺手改脸、发型主体、服装或背景。
- 女装电商批量生成时，版型和细节一致性必须优先。
- 如果选择了固定服装母版，必须锁定图2服装的版型和结构。
- 图2服装亮度、颜色深浅、面料光泽和同批曝光一致性，尤其要抑制 GPT 把原始服装颜色做浅、做白、做灰或做柔。
- 电商去褶皱语义：只去杂乱压痕和多余皱团，保留轻微松弛垂感、面料肌理和装饰结构。
- 抬手、扶头、弯曲手臂时的袖口相对落点约束。
- 换背景、换脸、设计稿等工作流的专属语义。

不应该写进 SKILL：

- 本地怎么裁剪。
- 本地怎么贴回。
- 本地怎么羽化。
- 本地怎么校色。
- 本地怎么对齐。
- 本地怎么保存。
- 本地怎么缓存。
- 本地怎么下载。
- 图3默认存在。

## 5. 本地后处理负责什么

本地后处理负责“模型出图之后”的确定性处理。

应该放在本地后处理：

- 局部结果贴回原图。
- 羽化融合。
- 蒙版融合。
- GPT 局部微对齐。
- Banana 边缘轻量校色，若保留该能力。
- 保留原图高分辨率画布。
- 结果缓存。
- 自动保存。
- 文件命名。
- 下载。
- 历史归档。
- 结果重刷候选、拖拽覆盖旧结果、清理重复候选卡。
- 图片代理和分片下载。

核心原则：

- 局部回贴的最终目标是本地原位贴回。
- 模型只负责生成局部变化内容。
- 最终画布、坐标、分辨率和贴回融合由本地控制。

## 6. 三图通道规则

### 6.1 图1

图1是主上传通道。

在女装电商批量生成中，图1通常是多个模特图，支持文件夹拖拽和批量上传。

图1代表：

- 原图。
- 模特身份。
- 姿态。
- 位置。
- 场景。
- 光影。
- 原始画布尺寸。
- 局部回贴坐标来源。

SKILL 可以描述图1的语义，但不要让模型随意重构图1。

### 6.2 图2

图2是固定需求通道。

在批量换装中，图2通常上传服装，可以上传多张，例如：

- 上衣。
- 裤子。
- 鞋子。
- 套装组合。
- 真人穿着参考。

无论上传几张，后台规则都要引导模型理解为“图2服装需求”，而不是多张无关参考图。

V6 开始，图2上装结构需要明确区分：

- 单件上衣：T 恤、衬衫、针织衫、卫衣、吊带、背心等单层上衣，不默认拆成外套+内搭，也不凭空增加第二件衣服。
- 外套+内搭：需要同时锁定外层开合、内搭外露范围、两层衣摆关系、领口层次和袖口关系。
- 套装/上下装组合：只有用户选择套装或同时勾选上装和下装时，才把图2下装、腰头、裙裤长度和上下装搭配关系一起迁移。

批量换装时，图2服装要尽量锁定：

- 服装类别。
- 版型。
- 穿法。
- 松量。
- 袖筒宽松度。
- 袖子是否卷起。
- 袖长。
- 袖克夫长度。
- 衣摆是否扎入。
- 领口。
- 衣长。
- 裤长。
- 门襟。
- 扣子扣合数量和开合状态。
- 扣子数量和位置。
- 缝线。
- 面料纹理。
- 厚薄和垂感。
- 是否休闲、宽松、正装、修身。

### 6.3 图3

图3是补充通道。

图3可以用于临时补充：

- 细节面料。
- 版型补充。
- 模特样貌。
- 发型替换。
- 局部五金。
- 临时风格说明。

图3规则：

- 默认不参与。
- SKILL 中不要默认写图3。
- 只有用户补充提示词明确提到图3、第三张、补充图、补充参考时，图3才参与。
- 图3参与时也只能服务用户明确说的补充目标，不能暗中影响主服装或主场景。

## 7. 批量换装 SKILL 重点

批量换装是项目核心。

女装电商场景下，换装不能只是“相似款”，必须尽量做到同一件服装在不同模特身上的一致性。

SKILL 应重点约束：

- 图1模特姿势和位置不变。
- 图1人脸、头发、手、背景、场景不变。
- 图1原服装不作为图2服装的任何参考；图1原衣服的袖长、袖口、松量、衣长、领口、扣子、扎法、颜色、面料和褶皱都不能覆盖图2服装事实。
- 图2服装是换装事实来源。
- 多个图1模特穿的是同一件图2服装，不是相似但不同尺码的款。
- 版型、袖长、袖克夫、袖筒松量、衣长、裤长、领口、扣子、门襟、缝线保持一致。
- 图2服装的穿法必须保持一致：衣摆扎法、袖子卷起或放下、扣子扣了几颗、拉链高度、腰带系法、领口打开程度都不能随机漂移。
- 宽松休闲款不要生成成正装感。
- 长袖不要漂移成九分袖、半袖或盖过手掌。
- 袖口位置、袖克夫长度和形状要按图2保持。
- 面料纹理和细节不要在不同模特间漂移。

注意：

- 不要为了锁定版型写过长、过硬、互相冲突的提示词。
- 优先把“图2服装母版分析”变成结构化辅助，再注入关键短句。
- 每次改批量换装 SKILL，都要用同一组图1模特和同一图2服装做 A/B 对照。

## 8. 局部回贴规则

局部回贴是核心底层能力，不是独立页面。

它应该嵌入到生图流程中：

- 快捷生成可触发局部回贴。
- 批量换装可触发局部回贴。
- 换背景、换脸、设计稿如果需要，也可以复用局部回贴底层能力。

局部回贴原则：

- 图1是原图和贴回坐标来源。
- 用户框选或涂抹的区域是允许变化区域。
- 模型生成局部变化。
- 本地程序贴回原图。
- 最终保留原图尺寸，例如 8K 原图仍保持 8K。
- 方便导入 PS 原位擦回人脸或其它区域。
- 选框交互属于前端能力，`Alt + 鼠标左键` 以选框中心缩放，不需要写入 SKILL。

SKILL 中可以写：

- 当前是局部换装或局部精修。
- 只改变用户点名区域。
- 保持图1其它内容。
- 图2只作为指定服装或局部细节来源。

SKILL 中不要写：

- 如何贴回坐标。
- 如何羽化。
- 如何蒙版。
- 如何保持 8K。
- 如何在 PS 里擦回。

这些都由本地流程保证。

## 9. 快捷生成规则

快捷生成是 P0。

快捷生成常见场景：

- 无图文生图。
- 单图参考。
- 多图参考。
- 图1局部精修。
- 图1局部换装。

原则：

- 普通快捷生成保持自由，不默认套批量换装规则。
- 普通裁剪只做上传图预处理。
- 只有图1开启局部回贴时，才触发局部保护逻辑。
- 只有明确是局部换装时，才引入换装相关短句。
- 小目标如扣子、袖口、口袋、污点优先走局部精修。
- 明确换衣、穿图2、整件替换时才走局部换装。

## 10. 换背景、换脸、设计稿规则

这些工作流与批量换装共用底层框架，但 SKILL 语义不同。

换背景：

- 图1是人物或商品主体。
- 图2是目标背景或场景。
- 保持图1主体身份、姿态、服装、边缘。

换脸：

- 图1是目标人物原图。
- 图2是脸型、发型、头饰和人脸身份母图。
- 图1锁定身体、服装、姿势、背景、构图、镜头距离、头部坐标、头部大小、脸部朝向、下巴、脖子肩线、头身比和原始光影。
- 图2提供身份、五官比例、脸型、年龄感、皮肤质感、妆容气质、发型整体轮廓、发量、发色、刘海、发缝、头饰、发饰和耳饰。
- 图1原脸型、原发型、原发饰和头饰只作为需要被覆盖的干扰源，不作为结果参考。
- 结果不能复制图2衣服、衣领、肩膀、身体、背景、拍摄角度或场景；不能换衣、换身体、换背景、移动人物或改变头身比。

设计稿：

- 图1和图2根据页面定义作为实拍、结构、款式、细节来源。
- 目标是设计稿或结构表达，不应误跑成普通换装。

自定义：

- 用户临时需求优先。
- 不默认套固定 SKILL。

## 11. 用户补充提示词负责什么

用户补充提示词用于表达本次临时需求，例如：

- 图3作为面料补充。
- 图3发型替换到图1。
- 袖口按图2更长一点。
- 裤脚保留拖地感。
- 不要改脸。
- 背景换成图2场景。

规则：

- 用户明确写到图3，图3才参与。
- 用户没有明确写到的补充图，不暗中参与。
- 用户临时需求不能覆盖 P0 稳定原则，例如不能让模型默认重构图1全部内容。

## 13. 改动红线

禁止事项：

- 不要让图3默认参与批量换装。
- 不要把局部贴回实现细节写进 SKILL。
- 不要让普通裁剪触发局部回贴 SKILL。
- 不要让快捷生成默认套批量换装 SKILL。
- 不要把图1原服装当成图2服装版型参考。
- 不要为了修一个模型的问题，破坏 GPT 局部回贴稳定链路。
- 不要在 UI 重构时顺手改 SKILL。
- 不要在 SKILL 调整时顺手改本地贴回算法。

## 14. 推荐优化方向

针对当前女装电商痛点，后续 SKILL 和后台规则优先优化：

1. 图2服装母版结构化分析。
2. 袖口、袖克夫、袖长一致性。
3. 版型松量一致性。
4. 图2穿法一致性，包括衣摆扎法、卷袖状态、扣子扣合数量、拉链高度和领口打开程度。
5. 衣长、裤长一致性。
6. 面料和细节一致性。
7. 宽松款不要正装化。
8. 多模特批量结果的一致性检测。
9. 局部回贴 GPT 链路继续加固。

## 15. GPT 批量局部回贴已知问题

当前观察：

- 非局部批量换装直接上传原图时，GPT 人物姿势保持效果正常，这条链路先不改。
- 批量局部回贴时，少数结果会出现图2未选中的服装部分被带入。
- 一部分结果会出现局部上下位置对不上、贴回偏移或融合不够自然。
- 当局部框选范围包含上方人脸一小半、下方腿部一部分时，脸部可能出现轻微糊化、肤色过渡不均、颜色没有充分晕染开的感觉。

后续处理原则：

- 优先从前端选区构造、本地贴回、融合羽化、保护区、色彩匹配和上传局部图构造排查。
- 不要先改非局部批量换装。
- 不要为了局部问题加重所有批量换装 SKILL。
- 如果需要调整 SKILL，只针对批量局部回贴触发，不污染普通批量换装和快捷生成。

这些比新增很多边缘功能更重要。
