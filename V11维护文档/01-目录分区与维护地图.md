# V11 目录分区与维护地图

本文档用于回答两个问题：

1. 想改某个功能时，应该先看哪个文件夹、哪个文件。
2. 后续继续拆分源码时，应该按什么边界拆，避免改一个功能牵动全局。

V11 当前策略：先保持 V10 界面和功能不变，再逐步正规化分区。不要一次性大搬 `main.jsx` 和 `outfit-workflow.jsx`，要按功能一块一块拆，拆完一块就运行检查和构建。

## 前后端功能分区规则

每个功能以后拆成两条线：

```text
src/features/<功能名>/       前端页面、状态、交互、功能私有样式
server/features/<功能名>/    后端路由、服务、上传处理、功能私有逻辑
prompts/<frontend|server>/   默认提示词和模型 SKILL
```

示例：

```text
src/features/outfit/
server/features/outfit/
prompts/server/outfit-skill.js
prompts/frontend/outfit-workflow-defaults.js
```

如果一个能力被两个以上功能共用，它不能放进某个功能私有目录，应放到：

```text
src/shared/
src/shared/ui/
server/shared/
src/lib/
prompts/
```

暂时无法抽共享组件时，必须登记到：

```text
D:\静音AI绘画V11（源码）\V11维护文档\02-重复功能同步登记表.md
```

## 一致性规则

1. 同一种 UI 控件只维护一套样式：按钮、弹窗、上传区、图库、任务状态、设置项，后续都应进入 `src/shared/ui/` 或统一 CSS token。
2. 同一个业务概念只维护一份配置：模型、尺寸、比例、并发默认值、局部编辑规则，优先放 `src/shared/` 或服务端配置文件。
3. 改主画板的快捷生成时，要同步检查批量页里是否有同名入口或复用逻辑，尤其是视频、参考生图、提示词助手、局部编辑。
4. 改批量生成的上传区、结果卡片、顶部工具栏时，要同步检查主画板图库和参考图缩略条，避免同类 UI 变成两种体验。
5. 后端接口字段一旦变更，要同时检查 `src/api/` 里的请求封装和调用该接口的功能页。
6. `server/static-assets.generated.js`、`dist/`、`data/`、`logs/`、`tmp/`、`node_modules/` 不手工维护。

## 调整功能时先看哪里

- 改 API 地址、模型、比例、价格展示：先看 `server/channel-config.js`、`server/video-config.js`、`src/shared/models.js`。
- 改 API 调用、KEY、登录授权、401、413、接口慢：先看 `V11维护文档/04-API调用与登录系统地图.md`、`src/api/README.md`、`server/features/api-gateway/README.md`。
- 改默认提示词、SKILL、出图规则：先看 `prompts/README.md`，再进 `prompts/server/` 或 `prompts/frontend/`。
- 改并发、排队、本地内存压力：先看 `server/index.js` 的 `IMAGE_CONCURRENCY_LIMIT` 和 `src/outfit-workflow.jsx` 的批量 worker。
- 改保存目录、打开文件夹、历史记录：先看 `src/api/save.js`、`src/api/history.js`、`server/index.js`。
- 改快捷生成界面：先看 `src/main.jsx`，搜索 `activeView === "quickgen"`。
- 改参考生图界面：先看 `src/main.jsx`，搜索 `reference-remix`。
- 改详情/主图：先看 `src/main.jsx` 搜索 `detail-main`，再看 `server/detail-*`。
- 改批量换装：先看 `src/outfit-workflow.jsx` 搜索 `OutfitWorkflow`、`startBatch`、`buildTasks`。
- 改批量扩图/改色/换脸等子页：先看 `V11维护文档/05-批量分区功能地图.md` 和 `src/features/outfit/workflows/<对应分区>/README.md`，再看 `src/outfit-workflow.jsx` 里的 `DEFAULT_*_PAGE_NAME`、`*_DEFAULT_PROMPT`、`is*Workflow`。
- 改局部回贴、涂抹蒙版：先看 `src/shared/local-edit-mask.js`，再看 `QuickLocalEditModal` 和 `OutfitLocalEditModal`。
- 改图片编辑器：先看 `src/image-editor.jsx`。
- 改发布包：先看 `scripts/secure-win-release.mjs`。

## 推荐拆分顺序

1. 先拆共享配置和工具：模型、尺寸、局部蒙版、图片压缩、文件名、格式化。
2. 再拆独立组件：上传区、结果卡片、设置弹窗、保存目录弹窗、提示词弹窗。
3. 再拆独立功能页：图片编辑、批量尺寸导出、提示词助手。
4. 再迁移前端默认提示词到 `prompts/frontend/`，每次只迁一个工作流。
5. 再拆主画板功能：快捷生成、参考生图、详情/主图。
6. 最后拆批量生成大工作流：先拆 `workflows/` 规则，再拆 UI，再拆任务构建和执行器。

每拆一步都至少运行：

```powershell
D:\RJ\node\npm.cmd run check
D:\RJ\node\npm.cmd run build
```
