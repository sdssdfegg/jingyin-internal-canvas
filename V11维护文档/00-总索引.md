# V11 维护文档总索引

这个文件夹专门放 V11 后续维护时要发给 Codex 的小文档。

目的：

1. 每次只发和本次任务相关的 1-3 个 MD，减少大文本堆积。
2. 避免上传整套源码、整段历史、整份大文件导致 413。
3. 让每个功能、每次改动都有清晰入口。

## 推荐发送方式

每次提需求时，优先发：

```text
00-总索引.md
本次功能对应的小 MD
如果涉及重复 UI，再发 02-重复功能同步登记表.md
如果涉及提示词/SKILL，再发 prompts/README.md
```

不要一次性发送：

```text
src/main.jsx
src/outfit-workflow.jsx
server/index.js
全部 docs
全部历史记录
node_modules
dist
logs
```

## 当前文档

| 文件 | 用途 | 什么时候发 |
| --- | --- | --- |
| `00-总索引.md` | 总入口和提问规则 | 每次都可以发 |
| `01-目录分区与维护地图.md` | 找功能在哪、前后端怎么分区、以后怎么拆 | 改任何功能前 |
| `02-重复功能同步登记表.md` | 避免只改一个重复 UI/逻辑，另一个没同步 | 改 UI、设置、上传、结果卡、提示词助手、视频等重复能力时 |
| `03-Codex提问模板.md` | 以后给 Codex 的标准提问格式 | 你不确定怎么描述需求时 |
| `04-API调用与登录系统地图.md` | API、KEY、登录授权、中转站链路、401/413/慢请求排查 | 改 API、登录、KEY、接口错误、多人出图慢时 |
| `05-批量分区功能地图.md` | 截图里每个批量 tab 对应哪个分区 | 单独改批量换装、姿态、换脸、背景、改色、白底、设计稿时 |

## 413 规避规则

413 通常是一次发送内容太大。以后按下面规则发：

1. 只发本次要改的功能名和需求。
2. 只发相关 MD，不发大源码。
3. 报错只截关键日志，不发整份 `generation.jsonl`。
4. 截图只发必要界面，不发一整批图片。
5. 如果要对比两个版本，只发差异描述和两个入口路径。

## 每次改动后要维护什么

如果本次新增了功能、移动了目录、抽了共享组件、迁移了提示词，要更新对应小文档：

```text
01-目录分区与维护地图.md
02-重复功能同步登记表.md
prompts/README.md
src/shared/ui/README.md
```

不需要把所有历史记录都继续写进大看板；大看板只适合阶段复盘，小文档适合日常维护。
