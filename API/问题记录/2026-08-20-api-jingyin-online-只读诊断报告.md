## 发现的问题

### API-2026-08-20-001 控制台图表加载失败

- 等级：P1
- 位置：`/console` 数据看板。
- 现象：模型数据分析区域显示“图表加载失败，请刷新重试”。
- 控制台错误：
  - `TypeError: Cannot read properties of undefined (reading 'createCanvas')`
  - `[DashboardChart] TypeError: Cannot read properties of undefined (reading 'filter')`
  - 报错文件集中在 `/static/js/async/4667...js` 和 `/static/js/async/4087...js`。
- 影响：无法直观看调用趋势、消耗分布、用户消耗排行，排查上游异常时少了关键视图。
- 初步判断：图表组件对空数据/异常数据缺少兜底，或图表渲染库的 canvas 初始化依赖异常。
- 建议处理：
  - 图表数据进入组件前统一兜底成空数组。
  - 图表初始化失败时不要抛出到整个面板，改成显示空状态。
  - 中转站源码可控后，在 DashboardChart 类组件中检查 `series?.filter`、`canvas` 初始化和 chart dispose 生命周期。

### API-2026-08-20-002 渠道响应时间过高，自动监控未开启

- 等级：P1
- 位置：`/console/channel`、`/console/setting` 运营设置。
- 现象：
  - 渠道列表显示 5 个 OpenAI 类型渠道。
  - 多个渠道响应时间很高：约 32.74 秒、62.23 秒、94.35 秒。
  - 有 1 个渠道显示“未测试”。
  - 运营设置里“定时测试所有通道”“失败时自动禁用通道”“成功时自动启用通道”看起来未开启。
- 影响：当某个上游慢或挂掉时，画板侧可能表现为长时间等待、超时、失败；中转站不能主动剔除坏渠道。
- 建议处理：
  - 给图片、视频、文本分开设置优先级，不要让慢渠道参与所有模型的默认轮询。
  - 开启定时通道测试，设置合理超时，例如 20-30 秒。
  - 开启失败自动禁用和成功自动启用。
  - 为高频模型单独保留最快渠道；慢渠道只作为低优先级备用。
  - 后续源码化时，用 `代码模板/failover-router.ts` 的结构做自动熔断。

- 现象：

  - `/console/models` 提示该处只影响模型广场展示，不影响真实调用与路由；当前展示搜索无结果。
  - 文档页却列出了 `gpt-5.5`、`nano-banana-pro`、`nano-banana`、`nano-banana2`、`gpt-image`、`sora2`、`veo31`、`kling` 等模型。
- 影响：真实调用可能能用，但后台展示和文档不一致，后续排查“模型是否配置/是否开放/怎么计费”时容易混淆。
- 建议处理：
  - 要么把模型广场配置完整，要么隐藏模型广场入口。
  - 模型展示信息至少包含：模型名、类型、支持参数、默认上游渠道、价格/倍率、是否推荐。

### API-2026-08-20-005 MjProxy 回调未开启

- 等级：P2
- 位置：`/console/midjourney`。
- 现象：页面提示“当前未开启 MjProxy 回调，部分项目可能无法获得绘图结果，可在运营设置中开启。”
- 同页观察：近期图片编辑任务状态为成功，但结果图片字段显示“无”。
- 影响：如果画板依赖异步绘图任务回调或结果追踪，可能出现任务成功但结果拿不到、后台不好定位的情况。
- 建议处理：
  - 如果画板只走同步 OpenAI 图片接口，可先确认影响范围。
  - 如果有异步任务、回调、任务日志展示需求，建议开启 MjProxy 回调并配置回调地址。
  - 后续问题记录里要区分“任务提交成功”和“结果回调成功”。

### API-2026-08-20-007 CORS 配置不严谨

- 等级：P2
- 位置：`OPTIONS /v1/chat/completions`。
- 观察到的响应头：
  - `Access-Control-Allow-Origin: *`
  - `Access-Control-Allow-Credentials: true`
  - `Access-Control-Allow-Headers: *`
- 影响：浏览器带凭据请求不允许通配 `*` origin；如果未来有网页端画板或管理页面直接调用 API，可能出现 CORS 失败。安全上也不建议对带凭据场景使用通配来源。
- 建议处理：
  - 如果不需要浏览器携带 cookie 调 API，去掉 `Allow-Credentials: true`。
  - 如果需要浏览器调用，改成白名单 Origin 回显，例如只允许画板域名和管理域名。
  - 保留桌面画板/服务端调用时，此问题优先级可低一些。

## 正常项

- 首页 `/` 返回 200。
- 文档 `/docs` 返回 200，内容能打开。
- 无密钥请求 `/v1/models` 返回 401 JSON。
- 无密钥或假密钥 POST `/v1/chat/completions` 返回 401 JSON。
- 无密钥 POST `/v1/images/generations` 返回 401 JSON。
- 错误响应带 `X-Oneapi-Request-Id`，后台日志可追踪。

## 建议优先级

1. 先修渠道稳定性：开启定时测试、自动禁用、自动启用，给高延迟渠道降权或仅作为备用。
2. 修控制台图表错误，让调用趋势、消耗分布能正常显示。
3. 补 Uptime/API 信息/公告/FAQ，把排查入口建起来。
4. 整理模型广场和文档，让“可见模型”和“真实可调用模型”一致。
5. 视画板调用方式处理 CORS。

## 后续记录规则

每次 API 出问题时，不要只记录“报错了”。至少记录这 6 个字段：

- 画板现象：比如超时、401、模型不存在、图片参数失败、视频任务无结果。
- 接口路径：比如 `/v1/chat/completions`、`/v1/images/edits`。
- 模型名：比如 `gpt-5.5`、`gpt-image`、`nano-banana-pro`。
- 渠道：后台日志里的渠道 ID/名称。
- Request ID：只记录脱敏或后台位置，不贴完整密钥。
- 结论：上游问题 / 中转转换问题 / 参数问题 / 配额问题 / 画板传参问题。
