# 2026-08-25 GPT 图片 2K 变 1K与老夜兜底失败

## 现象

- 画板选择 GPT 图片 2K，但实际结果看起来像 1K。
- 当前主要命中渠道：`lk888-gpt-image-2`。
- 禁用 `lk888-gpt-image-2` 后，`老夜的渠道` 接管 GPT 图片请求时生图失败。

## 后台观察

- New API 绘图日志里，同样是 `gpt-image` 图片编辑任务：
  - 有些记录显示：`gpt-image · 大小 1536x2304, 品质 standard, 生成数量 1`。
  - 近期多条记录只显示：`gpt-image · 品质 standard, 生成数量 1`。
- 日志有 `大小` 时，说明 New API/上游识别到了分辨率参数。
- 日志没有 `大小` 时，说明分辨率字段可能没有传到 New API 标准字段，或被标准化层过滤，最终上游可能按默认 1K 执行。

## 原因判断

### 1. `lk888-gpt-image-2` 2K 参数可能被过滤

- `lk888-gpt-image-2` 没有参数覆盖，未发现写死 1K。
- 该渠道此前 `透传请求体` 为关闭。
- 如果画板传的是上游自定义字段，例如 `image_size=2K`、`aspect_ratio=...`，New API 在 OpenAI 标准化过程中可能不会完整保留这些字段。
- 因此最小修复是只对 GPT 图片专用渠道开启请求体透传，让画板选择的分辨率参数原样交给上游。

### 2. `老夜的渠道` 缺少 GPT Image 2 重定向

- `老夜的渠道` 原本包含 `gpt-image`，但没有 `gpt-image-2`。
- 原本也没有 `gpt-image -> gpt-image-2` 的模型重定向。
- 当 `lk888-gpt-image-2` 被禁用时，画板请求 `gpt-image` 会落到老夜渠道，但老夜上游很可能实际需要 `gpt-image-2`，导致兜底失败。

## 追加确认：LK888 文档里的 2K 规则

用户打开并登录了 LK888 文档页：

- 文档站：`https://jingyin.kk0606.com/apidoc#model/tt-image-2`
- 基础地址：`https://api.lk888.ai`
- 普通 GPT Image 2 模型 ID：`tt-image-2`
- 官转 GPT Image 2 模型 ID：`tt-image-2-token`

文档确认：

- `tt-image-2` 和 `tt-image-2-token` 都走 LK888 自己的异步接口：
  - 创建任务：`POST /v1/media/generate`
  - 查询任务：`GET /v1/media/status?task_id=...`
- 请求体结构是 `model`、`prompt`、`params` 三段，图片尺寸参数在 `params.size`。
- 图生图参考图在 `params.images`，支持 URL 或 `data:image/...;base64,...`。
- 2K 尺寸应传精确像素值，不是单独传 `2K`：
  - `1:1` -> `2048x2048`
  - `2:3` -> `2048x3072`
  - `3:4` -> `1920x2560`
  - `4:5` -> `2048x2560`
  - `9:16` -> `1440x2560`
  - 横版按宽高对调，例如 `16:9` -> `2560x1440`
- 文档明确提示普通 `tt-image-2` 是性价比优先模型，选择 2K/4K 时分辨率、比例偶尔无法精准命中，部分价格优先渠道可能降采样。
- 文档建议：如果需要稳定精准高清，使用 `GPT Image 2 官转`，即 `tt-image-2-token`，价格更高但分辨率更有保障。

当前判断：

- `lk888-gpt-image-2` 在 New API 里是 OpenAI 类型渠道，画板请求路径仍是 `/v1/images/edits`，模型重定向是 `gpt-image -> gpt-image-2`。
- LK888 文档里的 `tt-image-2` / `tt-image-2-token` 不是普通 OpenAI `/v1/images/edits` 同形接口，而是异步 `media/generate + media/status`。
- 因此不能只在 New API 里把模型名硬改成 `tt-image-2-token`，否则可能出现接口路径和返回格式不匹配。
- 如果 LK888 另有 OpenAI 兼容别名，需要先确认该别名；确认前不建议直接改现有可用渠道。
- 若用户核心目标是客户稳定拿到 2K，优先方案是：接入 `tt-image-2-token` 对应的兼容渠道，或继续让老夜/其他稳定高清渠道承接 GPT 2K；普通 `tt-image-2` 只适合作为低价/速度优先渠道，不适合作为“保证 2K”的主渠道。

## 追加核验：LK888 文档关键词

- 普通 `tt-image-2` 文档页未出现 `/v1/images/edits` 或 `/v1/images`。
- 普通 `tt-image-2` 文档页明确出现：
  - `POST /v1/media/generate`
  - `GET /v1/media/status?task_id=...`
- 因此当前 New API 的 OpenAI 图片渠道如果仍按 `/v1/images/edits` 调用，和 LK888 文档展示的标准接入方式不是同一种协议。
- 结论保持不变：不要直接把当前可用渠道硬切成 `tt-image-2-token`；需要先确认 LK888 是否提供 OpenAI 兼容图片接口，或另做一个适配层把 OpenAI 图片请求转换为 LK888 异步媒体任务。
