# 2026-08-25 中转站重构启动和清理清单

## 背景

用户确认：画板仍应优先对接自己的中转站，由中转站负责识别不同上游协议。

已确认当前接入至少包含三类协议：

- 老夜：OpenAI 兼容图片接口，加 `image_size` / `aspect_ratio` 扩展参数。
- LK888：异步 `media/generate` + `media/status`。
- 7LAI：JSON 图片生成接口，参考图使用 `image_urls`。

## 当前核心问题

- 不同上游协议被当成同一种 OpenAI 图片接口硬套。
- 只靠模型重定向无法解决协议差异。
- 2K 参数可能在中转站标准化时被过滤或变成默认值。
- 异步任务如果用同步等待包装，会导致前端卡住或超时。
- 部分后台成功任务没有结果 URL，画板仍会等待。

## 作废内容

以下历史做法作废，不再作为后续方案：

- 自动定时测试图片渠道。
- 用定时测试结果判断图片渠道真实可用性。
- 把 LK888 GPT 当普通 OpenAI 图片接口主路由。
- 把 7LAI JSON 图片接口直接接到 OpenAI `images/edits` 文件上传链路。
- 只通过模型名重定向解决不同上游协议差异。

## 保留内容

- 老夜 GPT 图片渠道：当前仍可作为 GPT 图片主渠道。
- LK888 GPT 配置：保留，但适配器完成前不作为稳定 2K 主渠道。
- 7LAI 协议记录：保留；后台旧渠道配置已删除，后续需要按独立适配器重新接入。
- 现有问题记录：保留，作为排障历史。

## 待删除或待禁用清单

删除前必须确认，不直接删除：

- 已经无余额、无用途、无有效日志的旧渠道。
- 只支持 1K 的渠道，不允许参与 2K 路由。
- 后台成功但无法返回结果 URL 的渠道，不允许作为主渠道。
- 任何仅靠重定向伪装成另一种协议的渠道。
