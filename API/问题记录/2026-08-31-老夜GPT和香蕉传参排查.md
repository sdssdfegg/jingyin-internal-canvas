## 老夜文档对照

文档地址：

```text
https://api.luckfill.com/docs
```

当前文档写法：

```text
Base URL: https://api.luckfill.com/v1
图片文生图路径: /v1/images/generations
图片图生图路径: /v1/images/edits
模型名: nano-banana-pro | nano-banana | nano-banana2 | gpt-image
image_size: 1K | 2K | 4K
OpenAI 兼容接口推荐传 image_size 和 aspect_ratio
图生图/多图参考走 multipart/form-data
图片文件字段名重复使用 image
不要写 image[]
不要把图片 URL 填到 image 文件字段
```

关键差异：

- 老夜当前文档列出的 GPT 图片模型名是 `gpt-image`，不是 `gpt-image-2`。
- 中转站当前仍把 `gpt-image` 映射到 `gpt-image-2`，这与当前文档不一致。
- 老夜依赖扩展字段 `image_size` 和 `aspect_ratio`，但通道当前没有开启请求体透传，New API 的 OpenAI 标准化层可能会过滤这些非标准字段。

## 原因判断

当前最可疑的两个点：

1. 老夜 GPT 通道仍在做旧映射：`gpt-image -> gpt-image-2`。如果老夜当前推荐模型已改为 `gpt-image`，继续强行映射可能导致模型行为、尺寸解释或出图效果不一致。
2. 老夜 GPT 和香蕉都关闭了请求体透传。老夜文档推荐的 `image_size/aspect_ratio` 是 OpenAI 扩展字段，不是标准 OpenAI `size` 字段；关闭透传时，这两个字段可能被 New API 转换层吞掉，导致上游按默认尺寸/比例处理。
