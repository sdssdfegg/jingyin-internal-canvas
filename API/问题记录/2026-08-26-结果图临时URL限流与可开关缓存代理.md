# 2026-08-26 结果图临时 URL 限流与可开关缓存代理

## 背景

测试发现：公司网络会对部分上游结果图临时 URL 限流，导致画板下载结果图卡到 10 分钟甚至超时。

目标不是永久让所有图片都经过中转站，而是增加一个可开关功能：

- 网络好时：关闭缓存，画板继续直连上游结果 URL。
- 网络差或客户侧被限流时：开启缓存，由中转站服务器先下载结果图，再把中转站自己的稳定 URL 返回给画板。

## 结论

可以做，建议作为中转站独立模块：`结果图缓存代理`。

这属于中转站功能，不应该要求画板理解每个上游的临时 URL 规则。画板只需要接收一个结果图 URL。

## 推荐工作流

```text
上游返回结果图临时 URL
  -> 中转站判断结果图缓存开关
    -> 关闭：原样返回上游结果 URL
    -> 开启：中转站后台下载图片到本机或对象存储
      -> 返回 https://api.jingyin.online/result-cache/{task_id}/{file_id}
      -> 画板下载中转站稳定 URL
```

## 开关配置

建议至少提供以下后台配置：

| 配置 | 建议值 | 说明 |
|---|---:|---|
| 结果图缓存开关 | 关 / 开 | 一键切换。默认关闭，网络异常时开启。 |
| 磁盘清理阈值 | 50% | 磁盘或缓存目录占用达到 50% 时开始删除旧图片。 |
| 清理目标水位 | 45% | 删除到 45% 左右停止，避免频繁边界抖动。 |
| 图片保留时间 | 3-7 天 | 如果监管需要可保留 7 天；更重视磁盘则 3 天。 |
| 单图最大大小 | 50-100 MB | 防止异常文件撑爆磁盘。 |
| 允许缓存域名 | 白名单 | 只允许缓存已配置上游返回的图片域名，避免被滥用成开放代理。 |

## 前端体验规则

开启缓存后，不能让画板一直空等。

推荐返回任务状态：

```json
{
  "status": "processing",
  "cache_status": "downloading",
  "message": "结果图正在缓存到中转站"
}
```

缓存成功后：

```json
{
  "status": "succeeded",
  "cache_status": "ready",
  "image_url": "https://api.jingyin.online/result-cache/..."
}
```

缓存失败时：

```json
{
  "status": "succeeded",
  "cache_status": "failed",
  "image_url": "上游原始结果 URL",
  "warning": "中转站缓存失败，已回退上游 URL"
}
```

## 不建议做的事

- 不要默认永久开启，除非确认服务器带宽足够。
- 不要把结果图重新压缩成低质量图片；客户拿到的结果图质量优先。
- 不要把缓存接口做成任意 URL 代理，必须限制来源域名和任务归属。
- 不要在同一个 HTTP 请求里无限等待缓存完成，应该用任务状态轮询。

## 自动清理规则

建议双条件清理：

1. 超过保留天数的图片优先删除。
2. 缓存目录或磁盘占用达到 50% 时，按创建时间从旧到新删除，直到降到 45%。

删除只删除缓存文件，不删除任务日志和计费记录。

## 对速度的影响

关闭缓存：

- 不增加中转站带宽消耗。
- 速度取决于客户网络访问上游临时 URL 的速度。

开启缓存：

- 客户只访问中转站稳定 URL，可避开客户网络对上游临时 URL 的限流。
- 中转站服务器需要承担一次下载和一次对客户的上传。
- 如果中转站服务器到上游速度好，客户体验会明显稳定。
- 如果中转站服务器到上游也慢，则只能改善链接稳定性，不能保证立即变快。

## 实施前检查

上线前需要确认：

- 服务器磁盘容量和当前占用。
- 服务器带宽峰值是否能承受结果图下载。
- Nginx / 反代是否支持大文件、Range 分片、合理超时。
- HTTPS 域名是否已经可直接访问缓存文件。
- 缓存目录是否不和数据库、日志目录混在一起。

## 2026-08-26 雨云服务器只读观察

本次只读查看雨云后台，没有修改服务器配置，没有记录服务器地址或登录密码。

当前观察到的资源：

| 项目 | 当前值 | 判断 |
|---|---:|---|
| CPU / 内存 | 4 vCPU / 4 GB | 做轻量缓存代理可以，但不适合同时处理大量图片转码。 |
| 磁盘 | 30+ GB，监控显示 `/` 约 6.8 GB / 28.1 GB | 50% 水位约 14 GB，当前距离 50% 约还有 7 GB 可用缓存空间。 |
| 带宽 | 25 Mbps / 35 Mbps | 适合做“网络异常时开启”的缓存代理，不适合长期所有客户大图都走中转站。 |
| 当前负载 | CPU 和内存占用较低 | 增加缓存下载任务可行，但需要限制并发。 |

容量粗略估算：

- 如果单张结果图 5 MB，距离 50% 水位可容纳约 1400 张。
- 如果单张结果图 15 MB，距离 50% 水位可容纳约 470 张。
- 如果单张结果图 30 MB，距离 50% 水位可容纳约 230 张。

建议：

- 默认关闭结果图缓存代理。
- 开启后限制并发下载，例如 2-4 个后台下载任务。
- 缓存目录单独放置，避免挤占数据库、日志和系统空间。
- 达到 50% 立即按旧图删除，建议降到 45% 后停止。
- 如果后续客户量变大，应考虑对象存储或单独大盘服务器。
