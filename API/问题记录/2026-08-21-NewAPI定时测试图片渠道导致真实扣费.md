# 2026-08-21 New API 定时测试图片渠道导致真实扣费

## 基本信息

- 编号：API-2026-08-21-002
- 首次发现时间：2026-08-21 早上
- 发现人：用户反馈
- 状态：已止损，需长期禁止误开
- 等级：P1
- 影响范围：图片渠道、计费、通道监控、后台配置

## 现象

- 用户发现从 2026-08-20 晚上到 2026-08-21 早上，后台每隔约 10 分钟自动生成图片。
- 画板没有被修改，也不是画板主动循环点击生成。
- 后台现象符合 New API 的“定时测试所有通道”按间隔自动触发通道测试。
- 对图片模型来说，通道测试不是零成本心跳，而可能是真实调用图片生成接口。

## 涉及接口

- Base URL：`https://api.jingyin.online`
- 后台位置：`/console/setting?tab=operation`
- 配置项：`监控设置 / 定时测试所有通道`
- 接口类型：图片生成/图片编辑渠道测试
- 模型名：图片模型，包括 GPT 图像模型、香蕉图像模型等
- 上游渠道：所有被自动测试覆盖的图片渠道

注意：本记录不写真实 API Key、Token、手机号、IP、Cookie。

## 排查结果

- 当前后台已回读确认：
  - `monitor_setting.auto_test_channel_enabled`：关闭
  - `monitor_setting.auto_test_channel_minutes`：`10`
- 已执行一次“保存监控设置”，并刷新页面回读确认开关仍为关闭。
- `10` 分钟间隔本身不再生效，因为总开关已关闭。
- 之前的配置记录中曾保存过：
  - 定时测试所有通道：开启
  - 自动测试所有通道间隔时间：`10` 分钟
- 因此每 10 分钟自动出现图片生成记录的直接原因，是全通道定时测试曾被开启。

## 根因判断

初步根因：

- New API 的“定时测试所有通道”对图片/视频类渠道不是普通连通性检测。
- 它会按模型测试逻辑请求上游，图片模型可能触发真实图片生成。
- 之前为了自动发现坏渠道，开启了该开关并设置为 `10` 分钟，导致图片渠道被周期性真实测试和扣费。

证据：

- 后台监控设置存在 `定时测试所有通道` 和 `自动测试所有通道间隔时间`。
- 页面回读显示间隔值为 `10`。
- 用户看到的自动生成频率与该间隔一致。
- 图片模型测试会产生真实绘图调用，不是免费 ping。

## 修复方案

临时处理：

- 已关闭 `定时测试所有通道`。
- 已保存监控设置。
- 已刷新后台页面回读，确认开关仍为关闭。

长期规则：

- 禁止在生产环境开启 New API 的全通道定时测试，尤其是图片、视频、音频等可能真实计费的渠道。
- 图片/视频渠道只允许手动单渠道测试，且测试前必须明确确认“这次测试可能真实扣费”。
- 通道健康检查优先使用上游提供的 `/health`、余额查询、模型列表等轻量接口。
- 如果 New API 不支持按渠道设置零成本健康检查，则宁可关闭自动测试，由人工查看日志和手动测试。
- 自动禁用/自动启用可以保留，但不能依赖全通道定时测试触发。

需要调整的后台配置：

- `运营设置 / 监控设置 / 定时测试所有通道`：必须保持关闭。

需要改的中转站代码文件：

- 当前没有中转站源码可改。
- 如果后续有 New API 源码或自建适配层，建议把图片/视频渠道测试改成只走轻量健康检查，不发真实生成请求。

- 是否需要加入自动监控：不要用 New API 全通道定时测试做自动监控；改用轻量健康检查或人工日志巡检。
