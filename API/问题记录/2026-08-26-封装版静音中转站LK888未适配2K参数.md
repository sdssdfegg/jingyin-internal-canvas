# 2026-08-26 封装版走静音中转站时 LK888 2K 参数未适配

## 现象

- 源码版画板直连“测试2 / LK888”时，选择 2K + 3:4 可以生成 2K 图。
- 封装版画板走“静音中转站”时，同样选择 2K + 3:4，实际结果接近 1K。
- 静音中转站日志中可看到该请求走到 LK888 对应渠道，但输出尺寸不符合画板选择。

## 当前判断

问题不在 `tt-image-2` 模型名本身，也不是画板前端的 2K 选择失效。

根因是两条链路的参数协议不同：

1. 画板直连 LK888 时，会走“测试2 Provider Adapter”，把画板的 `2K + 3:4` 转换成 LK888 需要的精确像素参数：

   ```json
   {
     "model": "tt-image-2",
     "prompt": "...",
     "params": {
       "size": "1728x2304"
     }
   }
   ```

2. 画板走静音中转站时，只会发送通用参数：

   ```json
   {
     "model": "gpt-image",
     "prompt": "...",
     "n": 1,
     "image_size": "2K",
     "aspect_ratio": "3:4"
   }
   ```

3. 如果静音中转站把这条请求路由给 LK888，但没有把 `image_size=2K` + `aspect_ratio=3:4` 转换成 `params.size=1728x2304`，LK888 就可能按默认尺寸生成，导致实际变成 1K。

## 本地证据

- 封装版路径：`D:\RJ\JY-Canvas-Windows-V2026.08.26.1-20260826`
- 封装版 `data\api_providers.json` 当前主通道是 `jingyin`，base_url 是 `https://api.jingyin.online/v1`。
- 封装版 `API\.env` 当前没有 `API_PROVIDER_TEST2_KEY`，所以封装版不是在直连 LK888 测试2。
- `main.py:11241` 的 `test2_size_param_for_request()` 会计算 LK888 需要的精确尺寸。
- `main.py:11345` 直连 LK888 时会发送 `params = {"size": request_size}`。
- `main.py:11594-11645` 走静音中转站时发送的是 `image_size` 和 `aspect_ratio`，不是 LK888 专用的 `params.size`。

## 2026-08-26 前端报错：do_request_failed

### 前端错误

```text
上游生图接口错误：
{"error":{"message":"upstream error: do request failed (request id: 202608260935108281873988268d9d66rDOdfkq)","type":"new_api_error","param":"","code":"do_request_failed"}}
```

### 后台排查

- 使用日志按 Request ID 查询：无结果。
- 服务器原始日志按 Request ID 查询到真实错误：

  ```text
  do request failed: Post "https://api.luckfill.com/v1/images/edits": EOF
  channel error (channel #1, status code: 500): upstream error: do request failed
  POST /v1/images/edits | 500 | 1m0.172792358s
  ```

- 渠道页状态：
  - `老夜的渠道`：已启用，优先级 80。
  - `lk888-gpt-image-2`：已启用，优先级 40，有告警，最近响应时间约 57.70 秒。

### 判断

`do_request_failed` 是 New API 请求上游失败，失败发生在中转站到上游/适配器这一段，不是画板前端按钮或画板本地配置错误。

这条 Request ID 明确命中的是 `老夜的渠道 #1`，不是 LK888。

因为老夜优先级高于 LK888，GPT 图片请求会优先走老夜；老夜上游在 `/v1/images/edits` 连接中断或 60 秒未返回，就会让前端看到 `do_request_failed`。

LK888 的字段兼容修复已部署，后续如要验证 LK888，需要让 LK888 的优先级高于老夜，或临时禁用老夜后手动测试一张。

### 处理方案

1. 先不要连续点击生成，避免无效请求和可能扣费。
2. 登录服务器查看 New API 原始日志，按 request id 查真实命中的渠道。
3. 部署 LK888 适配器字段兼容修复。
4. 重启 `lk888-gpt-image-adapter.service`。
5. 再手动测试一张 GPT 2K 图，确认前端可收图且实际尺寸正确。

注意：

- `API地址` 不要带 `/v1`。
- 不要用参数覆盖写死 `size=1728x2304`，否则用户选 1K/2K/4K 会失效。
- 当前 New API 是服务器本机进程，不是 Docker 容器，所以 `127.0.0.1:8791` 可用。

## 2026-08-26 三次失败：LK888 返回参数 size 不合法

### 现象

源码版和封装版走静音中转站时，GPT 图生图仍可能失败。

最新服务器证据：

```text
2026-08-26 22:49:49
channel #5 lk888-gpt-image-2
POST /v1/images/edits

2026-08-26 22:50:04
adapter.log:
request_received contentLength=15049953 bodySource=chunked
request_failed status=502 error="参数 size 不合法"
```

### 根因

不是源码版或封装版的问题，也不是 `tt-image-2` 这个模型名的问题。

真正问题在静音中转站的 LK888 适配器：

- 适配器原来看到 `size=1086x1448`、`1024x1536` 这类像素尺寸时，可能会原样转给 LK888。
- LK888 不是所有像素尺寸都收，只能收它支持的固定尺寸或尺寸标签。
- 适配器原来只在 LK888 正常返回 JSON 错误体时才尝试降级重试；如果 LK888 直接用 HTTP 错误返回 `参数 size 不合法`，适配器会直接把错误抛给画板，没有重试。

### 修复动作

已更新并部署服务器文件：

```text
/opt/jingyin-lk888-gpt-image-adapter/server.py
```

本地代码模板也已同步到同版本：

```text
D:\静音AI绘画V11（源码）\API\代码模板\lk888-gpt-image-adapter\server.py
D:\静音AI绘画V11（源码）\API\代码模板\jingyin-lk888-gpt-image-adapter.zip
D:\静音AI绘画V11（源码）\API\代码模板\jingyin-lk888-gpt-image-adapter.tar.gz
```

服务器备份：

```text
/opt/jingyin-lk888-gpt-image-adapter/server.py.bak-20260826-225845-before-size-parity
```

修复内容：

- 增加 LK888 GPT 图片支持比例白名单：

  ```text
  1:1, 3:4, 4:3, 9:16, 16:9
  ```

- 增加 LK888 GPT 图片尺寸标签白名单：

  ```text
  1K, 2K
  ```

- `4K` 自动按 LK888 GPT 的能力降到 `2K`，避免上游直接拒绝。
- `image_size=2K + aspect_ratio=3:4` 转成 `size=1728x2304`。
- `image_size=2K + aspect_ratio=16:9` 转成 `size=2304x1296`。
- `size=1086x1448` 这类中间尺寸会先识别为 `3:4 + 2K`，再转成 `1728x2304`，不会原样转发。
- 如果 LK888 仍返回 `size invalid / 参数 size 不合法`，适配器会自动用 `2K` 标签再重试一次。
- 新增非敏感日志 `upstream_request_prepared`，只记录模型、尺寸、比例、图片数量，不记录提示词正文、不记录图片、不记录 Key。

## 验证标准

让画板发起一张经用户明确允许的 GPT 2K 测试图后，看适配器日志：

```text
画板入参：image_size=2K, aspect_ratio=3:4
适配器出参：params.size=1728x2304
LK888 创建接口：/v1/media/generate
LK888 轮询接口：/v1/media/status
返回格式：data[0].url
```

如果适配器已经转成 `1728x2304`，但结果仍是 1K，则问题从“中转站参数丢失”变成“LK888 普通模型降采样”，需要评估 `tt-image-2-token`。

## 临时方案

- 静音中转站里先不要让 `gpt-image` 的 2K 请求走未适配的 LK888 渠道。
- 如果需要 LK888 立即出 2K，可以让封装版补充 `测试2 / LK888` KEY 后直连测试2。

## 长期正确方案

- 静音中转站必须为每个上游做独立适配器。
- LK888 适配器需要把画板通用入参转换为 LK888 专用入参：
  - `model=gpt-image` 映射到 LK888 的 `tt-image-2`
  - `image_size=2K` + `aspect_ratio=3:4` 映射为 `params.size=1728x2304`
  - 其他比例也必须建立固定映射表
  - 按 LK888 的异步生成协议提交任务、轮询状态、再返回画板可识别的图片结果

## 避免再次发生

- 每个上游渠道必须有“能力表”和“参数映射表”，不能只做模型名重定向。
- 每次新增上游后至少测试：
  - 1K / 2K
  - 常用比例：1:1、3:4、4:3、9:16、16:9
  - 文生图和带参考图
- 静音中转站日志应记录：
  - 画板收到的原始参数
  - 中转站转发给上游的最终参数
  - 上游返回图片的真实宽高
