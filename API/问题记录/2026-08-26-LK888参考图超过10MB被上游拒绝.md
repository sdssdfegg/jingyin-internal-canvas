# 2026-08-26 LK888 参考图超过 10MB 被上游拒绝

## 基本信息

- 编号：API-2026-08-26-004
- 首次发现时间：2026-08-26 23:04
- 状态：已修复，待画板真实请求复测
- 等级：P1
- 影响范围：源码版/封装版画板走静音中转站、LK888 GPT 图生图、带参考图生成

## 现象

画板报错：

```text
上游生图接口错误：
{"error":{"message":"lk888_adapter_error","type":"lk888_adapter_error","param":"","code":null}}
```

源码版和封装版只要走的是静音中转站，都会命中同一个 LK888 适配器，所以源码版也可能失败。


## 根因

这次失败不是 `size` 参数错误，也不是画板源码/封装版差异。

真正原因是：

- 画板上传给静音中转站的参考图约 15MB。
- 静音中转站适配器原来会把 multipart 图片直接转成 `data:image/...;base64,...` 传给 LK888。
- LK888 对 `params.images[0]` 有单图解码后不能超过 10MB 的限制。
- 因为中转站没有提前压缩参考图，LK888 直接拒绝。

## 修复动作

已更新并部署：

```text
/opt/jingyin-lk888-gpt-image-adapter/server.py
```

本地模板同步：

```text

D:\静音AI绘画V11（源码）\API\代码模板\jingyin-lk888-gpt-image-adapter.zip
D:\静音AI绘画V11（源码）\API\代码模板\jingyin-lk888-gpt-image-adapter.tar.gz
```

服务器备份：

```text
/opt/jingyin-lk888-gpt-image-adapter/server.py.bak-20260826-231202-before-input-image-compress
```

修复内容：

- 服务器安装 `python3-pil` 用于图片压缩。
- LK888 适配器新增上传图压缩逻辑。
- multipart 上传图片超过 9.5MB 时，会在转发给 LK888 前自动压缩成 JPEG。
- 默认压缩上限：`LK888_MAX_UPSTREAM_IMAGE_BYTES=9500000`。
- 默认开启压缩：`LK888_COMPRESS_INPUT_IMAGES=true`。
- URL 图片不下载、不压缩，继续原样转发，避免中转站额外耗时。
- 日志只记录压缩前后大小、宽高、质量参数，不记录图片内容、不记录提示词、不记录 Key。

## 后续复测

用户用画板再发同类带参考图请求后，查看：

```text
/opt/jingyin-lk888-gpt-image-adapter/adapter.log
```

正常应看到：

```text
input_image_compressed
upstream_request_prepared
```

如果仍失败，继续看 `request_failed.error` 的真实错误内容。

## 避免再次发生

- 所有带图上游适配器都要明确记录上游的单图大小限制。
- 对 multipart 上传图，先在中转站压缩到上游限制以下，再转发。
- New API 返回给画板的 500 错误会被隐藏，排查时必须看适配器日志的真实错误。
