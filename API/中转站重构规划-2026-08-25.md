# 中转站重构规划 - 2026-08-25

## 目标

画板只对接一个稳定入口：`https://api.jingyin.online/`。

中转站内部必须知道每个上游是什么协议，不能把所有图片上游都硬套成 OpenAI 图片接口。后续所有上游接入都按“协议适配器”管理。

## 总体结构

```text
画板统一请求
  -> 静音统一网关
  -> 模型能力路由
  -> 协议适配器
  -> 老夜 / LK888 / 7LAI / 其他上游
```

画板只传统一业务参数：

```json
{
  "model": "gpt-image",
  "task_type": "image_edit",
  "resolution": "2K",
  "aspect_ratio": "3:4",
  "quality": "standard",
  "prompt": "...",
  "images": []
}
```

中转站负责转换成上游真实参数。

## 已确认上游分类

### 老夜

协议类型：OpenAI 兼容图片接口，加自定义图片参数。

关键接口：

- 文本：`POST /v1/chat/completions`
- 文生图：`POST /v1/images/generations`
- 图生图：`POST /v1/images/edits`

关键参数：

- `image_size`: `1K` / `2K` / `4K`
- `aspect_ratio`: 例如 `1:1`、`16:9`、`9:16`、`4:3`、`3:4`
- 图生图使用 `multipart/form-data`
- 多图文件字段重复使用 `image`
- 不使用 `image[]`

适配结论：

- 老夜可以作为当前 GPT 图片主渠道。
- 老夜不是纯标准 OpenAI；必须保留 `image_size`、`aspect_ratio`，否则可能丢失 2K/比例。
- New API 如果过滤自定义字段，需要对图片渠道开启或实现请求体透传。

### LK888

协议类型：异步媒体任务接口。

关键接口：

- 创建任务：`POST /v1/media/generate`
- 查询任务：`GET /v1/media/status?task_id=...`

关键参数：

- `model`: `tt-image-2` 或 `tt-image-2-token`
- `params.size`: 精确像素字符串，例如 `2048x2048`、`1920x2560`、`2560x1440`
- `params.quality`
- `params.images`

适配结论：

- LK888 GPT 不能继续当普通 OpenAI `/v1/images/edits` 渠道硬套。
- 普通 `tt-image-2` 可能 2K/4K 降采样。
- 稳定高清应评估 `tt-image-2-token`，但必须走 LK888 异步适配器。
- 没有适配器前，LK888 GPT 不应作为 GPT 2K 主渠道。

### 7LAI

协议类型：JSON 图片生成接口，不是标准 OpenAI 图生图接口。

关键接口：

- 图片：`POST /v1/images/generations`
- 视频：`POST /v1/videos/generations`

关键参数：

- `prompt`
- `model`
- `aspect_ratio`
- `image_size`
- `n`
- `image_urls`

适配结论：

- 7LAI 图片参考图走 `image_urls` 数组，不是 OpenAI `multipart image`。
- 如果画板发的是 `/v1/images/edits` + 文件上传，不能直接路由到 7LAI 生成接口。
- 7LAI 需要单独适配器，把图生图文件先转成可访问 URL 或 Data URI，再填到 `image_urls`。

## 统一适配器规则

每个上游必须单独一个适配器，至少声明：

```text
上游名称
协议类型
支持模型
支持任务类型：文生图 / 图生图 / 多图 / 视频 / 文本
支持分辨率
支持比例
是否异步
创建任务路径
查询任务路径
请求参数映射
结果 URL 字段
错误字段
价格规则
超时规则
是否可作为主渠道
是否只允许兜底
```

## 路由原则

不要只靠模型名和优先级路由，要先检查能力。

示例：

```text
GPT 图片 2K:
  1. 优先支持 OpenAI 图片接口且能保留 image_size/aspect_ratio 的渠道
  2. LK888 只有在异步适配器完成后才能参与
  3. 不允许 1K-only 渠道参与

香蕉图生图:
  1. 优先支持 multipart images/edits 的渠道
  2. 7LAI 需要图片转 URL 适配后才能参与
  3. 后台成功但结果 URL 为空的渠道不能作为主渠道

视频:
  1. 全部按任务制处理
  2. 不允许 HTTP 长连接一直等视频完成
```

## 防止 2K 变 1K

中转站必须记录三层日志：

```text
画板入参：resolution=2K, aspect_ratio=3:4
上游出参：image_size=2K 或 params.size=1920x2560
结果校验：实际图片宽高
```

判断规则：

- 入参是 2K，出参变成 `auto` 或缺失：中转站参数映射错误。
- 出参是 2K，结果仍是 1K：上游降采样或不支持。
- 日志没有结果 URL：结果回传/格式化问题。

## 防止卡时间

同步图片接口：

- 普通图最大等待：120 秒。
- 2K 图最大等待：180 秒。
- 超过后返回明确状态，不要让画板无限等待。

异步图片/视频接口：

- 中转站创建本地任务 ID。
- 后台轮询上游。
- 画板轮询中转站任务状态。
- 不用单次 HTTP 请求一直等完成。

## 结果图缓存代理

新增可开关的结果图缓存代理，用来解决客户网络访问上游临时 URL 被限流的问题。

```text
上游结果图临时 URL
  -> 缓存开关关闭：原样返回给画板
  -> 缓存开关开启：中转站服务器先下载并落盘
    -> 返回中转站稳定图片 URL
```

设计规则：

- 默认关闭，网络异常或客户侧访问上游 URL 慢时一键开启。
- 开启后只缓存任务结果图，不做任意 URL 代理。
- 不重新压缩结果图，优先保证客户收到原质量图片。
- 缓存目录达到 50% 水位时，按旧图优先删除，建议删除到 45% 停止。
- 可叠加 3-7 天保留时间，缓存文件删除不影响日志和计费记录。
- 支持 Range / 分片下载，避免大图下载中断后从头开始。
- 缓存失败时回退上游原始 URL，并记录 `cache_status=failed`。

状态字段建议：

```json
{
  "cache_enabled": true,
  "cache_status": "downloading|ready|failed|bypassed",
  "image_url": "最终给画板使用的 URL",
  "origin_image_url": "仅后台排查使用，不返回给普通客户"
}
```

## 当前清理原则

先隔离，再删除。

立即作废：

- 用“模型重定向”假装完成协议适配的做法。
- 自动定时测试图片渠道的方案。
- 把 LK888 GPT 当 OpenAI 图片接口直接主路由。
- 把只支持 JSON `image_urls` 的 7LAI 直接接到 OpenAI `images/edits` 文件上传链路。

保留但降级：

- 老夜 GPT 图片：当前主渠道。
- LK888 GPT 图片：保留配置，完成异步适配前只做观察/低优先级，不做 2K 主渠道。
- 7LAI 香蕉/图片：完成 `image_urls` 适配前，不承接画板 multipart 图生图主链路。

删除前确认：

- 已无余额、已不用、没有历史有效日志的旧渠道。
- 已被新适配器完全替代的旧渠道。
- 任何涉及客户正在使用模型的渠道。

## 执行阶段

### 第一阶段：配置止损

- 停止自动定时测试会扣费的图片渠道。
- GPT 2K 先走老夜。
- LK888 GPT 不再作为普通 OpenAI 图片主路由。
- 7LAI 不直接承接 OpenAI 图片编辑文件上传。

### 第二阶段：适配器设计

- 新建老夜 OpenAI 图片适配器。
- 新建 LK888 异步 GPT 图片适配器。
- 新建 7LAI JSON 图片适配器。
- 新建统一任务状态与轮询格式。

### 第三阶段：日志与校验

- 入参、出参、结果宽高全部记录。
- 每个失败记录命中渠道、请求路径、错误字段、是否重试。
- 生成问题记录时不保存 key、IP、手机号。

### 第四阶段：逐个上线

- 每次只启用一个新适配器。
- 每次只测 1-2 个低风险请求。
- 测试前必须确认是否允许产生扣费。
- 观察成功率、耗时、结果尺寸后再提高优先级。
