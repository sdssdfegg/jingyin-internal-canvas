# API 中转站建议配置方案

> 2026-08-25 修正：本文是早期方案，部分内容已经作废。尤其不要再开启“自动定时测试图片渠道”，历史已经确认会触发真实扣费。新的执行依据以 `中转站重构规划-2026-08-25.md` 和 `渠道能力表-2026-08-25.md` 为准。

目标：中转站只做轻量控制、计费、路由、日志和错误归因；大图片下载尽量不经过中转站。

## 建议现在在 New API 后台保存的配置

### 1. 运营设置 / 监控设置

状态：已作废，不能直接执行。

建议改动：

- 不再建议开启：定时测试所有通道
- 不再建议设置：自动测试所有通道间隔时间
- 不再建议通过后台自动测试图片渠道判断可用性
- 开启：失败时自动禁用通道
- 开启：成功时自动启用通道
- 自动禁用状态码：暂时保持 `401`
- 自动重试状态码：暂时保持当前配置
- 自动禁用关键词：暂时保持当前配置

原因：

- 当前渠道响应时间有 30 秒、60 秒、90 秒级别，5 秒作为全渠道测试超时过于激进，容易误伤慢渠道。
- 图片渠道测试可能触发真实生图扣费，不能作为常规定时探活方式。
- 图片/视频渠道应使用轻量非付费探活，或仅由用户确认后做受控测试。

风险：

- 若需要自动禁用，只能基于真实业务失败率、非付费健康检查或明确错误码。
- 图片渠道不允许后台每隔固定时间自动生成图片。

### 2. 绘图设置

建议改动：

- 关闭：开启之后将上游地址替换为服务器地址

原因：

- 你的目标是“下载的图片不经过中转站”，这个开关当前是开启状态，和目标冲突。
- 关闭后，结果图更倾向保留上游/对象存储直链，中转站只记录任务和轻量信息。

风险：

- 如果某些上游返回的图片 URL 在客户端不可访问，关闭后画板可能拿不到图。
- 需要画板侧支持直接下载结果 URL。

### 3. 性能设置 / 磁盘缓存

建议改动：

- 开启：启用磁盘缓存
- 磁盘缓存阈值：保持 `10 MB`
- 磁盘缓存最大总量：保持 `1024 MB`
- 缓存目录：保持空，使用系统临时目录

原因：

- New API 页面说明该功能适合包含大量图片/文件的请求。
- 图生图、多图参考上传时，大请求体临时落磁盘比直接吃内存稳定。

风险：

- 当前服务器可用空间约 21.58 GB，1 GB 缓存上限可接受。
- 如果磁盘 IO 很慢，可能影响大请求吞吐；看起来当前缓存目录在 `/tmp/new-api-body-cache`。

## 暂不建议我直接改的配置

### 1. 允许回调

当前关闭，暂时不动。

原因：页面提示会泄露服务器 IP。如果不是必须依赖 MjProxy 异步回调，不建议贸然开启。

### 2. Worker 地址 / 图片请求转发代理

当前后台有 Worker 设置，但需要真实 Worker 地址和密钥。没有这些信息时不应乱填。

如果以后要做图片下载分片/CDN/对象存储，推荐用：

- 对象存储直链
- CDN
- 支持 HTTP Range 的下载服务
- Nginx `X-Accel-Redirect` 或对象存储签名 URL

不要让 New API 本身长期代理大图片下载。

### 3. 渠道优先级和权重

这项需要结合每个上游实际模型能力、价格、成功率和用途拆分。

建议后续按模型类型拆：

- 文本渠道：`gpt-5.5` 等
- 图片渠道：`gpt-image`、`nano-banana-*`
- 视频渠道：`sora2`、`veo31`、`kling*`

不要让高延迟视频/图片渠道参与文本默认路由。

## 需要服务器或源码层处理的内容

### 1. 网关压缩

New API 后台没有看到明确的全局 gzip/brotli 开关。

建议在 Nginx 或 CDN 层处理：

- 对 JSON、文本、SSE 轻量数据启用 gzip/brotli
- 不要对 JPEG/PNG/WebP/MP4 二次压缩
- SSE 流式响应要谨慎，避免压缩缓冲导致首字变慢

### 2. 上传图片压缩

New API 后台没有看到上传图片自动压缩开关。

建议由画板本地做第一层压缩，中转站只做大小限制和格式校验。

### 3. 下载图片分片

New API 后台没有看到图片下载分片开关。

建议由对象存储/CDN/上游直链支持 HTTP Range，不建议中转站手写分片。
