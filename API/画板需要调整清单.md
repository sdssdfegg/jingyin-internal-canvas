# 画板需要调整清单

这份清单只给画板侧使用。API 中转站仍然保持 `https://api.jingyin.online/` 作为唯一入口。

## 1. API 地址

- 如果画板配置项是 Base URL，并且请求路径由画板拼接：
  - 使用：`https://api.jingyin.online/v1`
- 如果画板内部已经会自动拼 `/v1`：
  - 使用：`https://api.jingyin.online`
- 不要在画板里配置多个上游 API。
- 不要让画板知道中转站背后的上游地址。

## 2. 上传图片前本地压缩

普通参考图建议：

- 最长边：2048-3072 px
- JPEG/WebP 质量：85%-90%
- 去掉 EXIF
- 尽量避免 base64

人脸、商品、文字、细节参考图建议：

- 最长边：3072-4096 px
- JPEG/WebP 质量：90%-95%
- 不要强压到很小
- 不要破坏透明 PNG

不要一刀切压缩所有图片。人物一致性、商品细节、文字图、LOGO 图压太狠会明显影响生成质量。

## 3. 图生图上传格式

图生图、多图参考使用 `multipart/form-data`。

字段规则：

- 文件字段名重复使用：`image`
- 多张图就传多个 `image`
- 不使用：`image[]`
- 不把图片 URL 填进 `image` 文件字段

示例：

```text
model=nano-banana-pro
prompt=保留人物特征，改成电影海报风格
image_size=4K
aspect_ratio=16:9
image=@reference_1.jpg
image=@reference_2.jpg
```

## 4. 结果图片下载

- 画板拿到结果 URL 后，直接从结果 URL 下载。
- 不要让结果图片下载再经过 `https://api.jingyin.online/`。
- 大图下载如果需要断点续传/分片，依赖结果 URL 所在服务的 HTTP Range/CDN。
- 画板只需要保存任务 ID、结果 URL、模型、价格、错误信息。

## 5. 超时建议

文本模型：

- 首字超时：15-30 秒
- 总超时：120-300 秒

图片生成/编辑：

- 总超时：180-600 秒
- 如果接口返回任务 ID，画板应轮询任务状态，不要一直阻塞 UI。

视频生成：

- 必须按任务制处理。
- 画板只提交任务、轮询状态、拿结果 URL。
- 不建议用一次 HTTP 长连接等待视频完成。

## 6. 错误记录

画板遇到 API 错误时，请保存这些字段，方便中转站排查：

- 接口路径
- 模型名
- HTTP 状态码
- 返回体里的 `error.message`
- 返回头里的 Request ID，常见为 `X-Oneapi-Request-Id`
- 是否重试
- 是否有结果 URL

不要在画板日志里明文保存 API Key。

## 7. 画板不需要做的事

- 不需要管理多个上游 API。
- 不需要知道渠道优先级。
- 不需要处理上游差异。
- 不需要代理下载图片。
- 不需要保存上游密钥。
